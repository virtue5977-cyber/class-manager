# 담임 업무 앱 (출결 · 학급 · 상담일지 · 오늘의 전달사항) 설계

작성일: 2026-11-04 / 개정 9 / 상태: 사용자 검토 대기
1단계 = 노트북 전용(데이터 서버 없음). 폰 연동·암호화 동기화는 2단계로 보류(부록 A).

## 1. 목적과 성공 기준

**누가:** 담임교사 1명(개인용). 1단계는 노트북 1대에서 사용.
**왜:** 엑셀 매크로 "개인 상담 프로그램(2025)"을 대체하고, 출결·결석신고서·상담 기록(나이스 누가기록 정리)·학급 배치표·조/종례 전달사항까지 한 앱에서 처리. 학생 개인정보는 기기 밖으로 나가지 않는다(예외: 사용자가 직접 누르는 AI 정리, 이름을 가린 뒤 전송).

**성공 기준**
- 오늘 출결 이상자(결석·지각·조퇴·결과)를 30초 안에 입력할 수 있다.
- 결석 출결을 입력하면 결석신고서가 자동 생성되고, 월말에 미제출 목록만 보고 정리할 수 있다.
- 개조식 메모나 녹취 텍스트를 넣으면 나이스 누가기록에 붙여넣을 형식으로 정리된다.
- 명렬표, 자리배치표, 청소배치표를 편집하고 A4로 출력할 수 있다.
- 인터넷이 없어도 입력·조회·신고서 생성·출력이 된다(AI 정리와 NEIS 가져오기만 인터넷 필요).
- 하루 한 번 암호화된 백업 파일이 지정 폴더에 자동 저장되고, 백업에서 완전히 복원할 수 있다.
- 학교 메신저·공문에서 복사한 전달사항을 붙여넣으면 조례/종례용 체크리스트가 나온다.

## 2. 범위

**포함(1단계)**
1. 홈: 오늘 학사일정·급식·내 시간표, 조례/종례 전달사항(AI 정리), 다가오는 학사일정
2. 출결: 일일 체크, 결석신고서 자동 생성
3. 학급: 명단·인적사항(보호자 성함·번호 포함), 명렬표 출력, 자리배치표, 청소배치표
4. 상담일지: 학생별 날짜·내용 누적, 검색, 인쇄, 엑셀 내보내기, **누가기록 형식 AI 정리**
5. 결석신고서: 월별 목록, 제출·진단서 수령 체크, hwpx 생성, 양식 갱신
6. 통계: 학생별 누적 출결 통계
7. 설정: 담임 성명, NEIS 키·학교 설정, 암호화 자동 백업·복원, 선택적 PIN 잠금, AI 키와 스위치, AI 프롬프트 편집(누가기록·전달사항)

**제외 / 보류**
- 폰 사용, 기기 간 동기화, 로그인, 서버 → 2단계 보류(부록 A)
- 다중 사용자, 학부모·학생 접속
- 학교 메신저·나이스 출결·누가기록의 자동 입력(복사해서 붙여넣는 방식)
- 앱 안의 음성 인식(녹취 텍스트는 이미 텍스트로 있는 것을 붙여넣음)
- 교시별 출결 전수 관리, 월마감 기능(통계로 대체)

## 3. 아키텍처

- **형태:** React + TypeScript + Vite 웹앱. 개발·검증은 웹앱으로 하고, **최종 배포는 Electron 포터블 exe**(설치 없이 실행)로 포장한다. 크롬에서 "앱으로 설치"해 쓰는 PWA로도 동작하게 유지한다. 학생 데이터는 어디에도 올라가지 않는다.
- **어댑터 구조:** 저장(`lib/db`), 파일·백업(`lib/fsAdapter`), 네트워크(`lib/net`)를 어댑터 뒤에 둔다. 웹에서는 브라우저 API를, exe에서는 Electron의 파일·네트워크 기능을 쓴다. 덕분에 exe에서는 폴더 권한 재확인 없이 백업하고 NEIS 호출의 브라우저 제약(CORS)도 받지 않는다.
- **기기 저장소:** IndexedDB(Dexie). 조회·검색·통계 모두 기기에서 계산.
- **데이터 접근 경계:** 모든 읽기·쓰기는 `lib/db` 한 곳을 통한다. 모든 레코드에 `id`(uuid), `created_at`, `updated_at`, `deleted`(2단계 동기화 대비).
- **암호화 백업:** File System Access API로 사용자가 지정한 폴더에 하루 1회(앱 실행 시 마지막 백업이 24시간 넘었으면) 암호화 백업 파일을 저장하고 최근 N개만 유지(4절). 폴더 접근 권한을 브라우저가 다시 물을 수 있으므로 권한이 없으면 시작 때 한 번 허용을 요청한다.
- **NEIS:** 사용자의 NEIS 교육정보 개방 포털 인증키로 학사일정, 급식식단, 학급 시간표를 가져와 `neis_cache`에 저장(오프라인 표시용).
- **AI:** 사용자의 Claude API 키를 설정에 입력해 기기에만 저장하고, 앱에서 직접 호출한다. 서버를 두지 않는다.
- **인쇄:** 브라우저 인쇄(@page A4, 가로·세로 선택)와 PDF 저장. 명렬표는 엑셀(xlsx) 내보내기도 지원.
- **hwpx 생성(모든 출력물의 기본 형식):** 두 갈래로 만든다. ① `lib/hwpx/fill` — 고정 양식 채우기: 제공된 "결석신고서 생성기" HTML의 로직(JSZip으로 원본 서식 hwpx 조작)을 TypeScript로 이식. ② `lib/hwpx/build` — 표 생성: 명렬표·자리배치표·청소배치표·상담일지·통계처럼 행·열 수가 바뀌는 문서를 내장 기본 양식(쪽 설정·글꼴·표 스타일)을 바탕으로 표 XML을 만들어 hwpx로 저장. 자리배치표 기본 양식은 사용자가 제공한 예시 hwpx의 구성(A4 가로, 제목, 책상 상자, 교탁, 오른쪽 명렬표)을 따른다.

**모듈 경계:** `lib/db`, `lib/backup`(암호화·복원·자동 백업), `lib/fsAdapter`, `lib/net`, `lib/schoolDays`, `lib/absenceReports`, `lib/hwpx`, `lib/stats`, `lib/neis`, `lib/ai`(호출·이름 가리기·프롬프트), `lib/nuga`(누가기록 정리), `lib/seating`, `lib/cleaning`, `lib/print`. 화면은 이 모듈들만 호출한다. 각 모듈은 UI 없이 단위 테스트가 가능해야 한다.

## 4. 데이터 보호

### 4.1 PIN 잠금(선택)
설정에서 켜고 끈다. 4~8자리, 솔트와 함께 해시로 저장. 앱을 켤 때(종료 후 다시 실행)와 노트북이 절전·화면 잠금에서 돌아올 때만 잠금 화면을 띄운다. 사용 중 유휴 시간 잠금은 하지 않는다. exe에서는 시스템 절전·잠금 이벤트로 감지하고, 웹 실행 시에는 앱 시작 때만 잠근다. **PIN은 화면 접근을 막는 장치이지 저장 데이터를 암호화하는 것은 아니다.** 노트북의 화면 잠금과 계정 보안이 기본 방어다. PIN을 잊으면 앱 데이터를 초기화하고 백업(백업 암호구 필요)에서 복원한다.

### 4.2 백업 암호화
- 백업은 항상 암호화한다. 첫 실행 때 백업 암호구를 정한다.
- 키 유도: PBKDF2-SHA256, 반복 600,000회 이상, 암호구를 정할 때 한 번 만드는 무작위 salt(무인 자동 백업 때 키를 다시 유도하지 않기 위함). 암호화: AES-GCM-256, 파일마다 무작위 IV. 파일 머리말에 버전·salt·반복 횟수를 담아 다른 기기에서도 암호구만으로 복원할 수 있게 하고, 머리말은 추가 인증 데이터(AAD)로 묶어 변조를 인증 실패로 탐지한다.
- 무인 자동 백업을 위해 유도 키를 추출 불가능한 CryptoKey로 기기에 보관한다. 복원할 때는 암호구를 입력해야 한다.
- 파일명: `백업_YYYYMMDD_HHMM.enc`. 보관 개수는 설정(기본 14개).
- **암호구를 잃으면 백업 파일은 복구할 수 없다.** 설정과 첫 설정 화면에서 종이 등에 적어 두라고 안내한다.
- AI 키·NEIS 키는 백업에서 제외한다.

### 4.3 기타
- 브라우저 저장소 영구 보관 요청(`navigator.storage.persist`)을 시작 때 시도한다. 그래도 백업이 근본 안전장치다.
- 학생 데이터는 기기 안에만 있고, 외부로 나가는 것은 AI 정리를 누른 텍스트(이름 가림)뿐이다.

## 6. 핵심 규칙

### 6.1 수업일
- 수업일 = `school_calendar`에서 `is_class_day=true`인 날. 일정이 없는 날은 평일이고 공휴일이 아니면 수업일로 간주(공휴일은 NEIS 일정 또는 내장 목록).
- 신고서의 "N일간"은 수업일만 센다. 주말·공휴일·휴업일·방학은 세지 않고, 연속 여부 판정에서는 이어진 것으로 본다.

### 6.2 신고서 자동 생성
신고서를 만들 출결 상황은 설정의 **구분(결석·지각·조퇴·결과) × 종류(미인정·질병·출석인정) 12칸 체크표**(`report_rules`)로 정한다. 기본값:
- 질병 + 결석
- 출석인정 + (결석, 지각, 조퇴, 결과 전부)

진단서가 필요한 질병 결석 일수(`diagnosis_days`, 기본 3)도 설정으로 둔다. 아래 "2일 이내/3일 이상"은 이 값 기준이다.

- **결석:** 같은 학생, 같은 category의 결석이 수업일 기준으로 이어지면 신고서 한 장으로 병합. 출결이 추가·수정·삭제되면 다시 계산.
- **지각·조퇴·결과:** 날짜·교시마다 신고서 1건.
- **작성일·확인일:** 기본값은 종료일(하루면 시작일)의 다음 수업일(기존 생성기와 같음). 직접 고칠 수 있다.
- **증빙(4번):** 질병 결석 수업일 2 이하 → `2일 이내 질병` + 보호자 통화(문자) 확인. 3 이상 → `3일 이상 질병` + 진단서 필요 표시. 출석인정 → 출결의 evidence_type 사용. 사유 문구(detail)는 출결의 reason을 40자 이내로 사용하고 고칠 수 있다.
- 사용자가 신고서를 직접 수정하면 `manual_override=true`. 이후 출결이 바뀌어도 수정한 칸은 덮어쓰지 않고 변경 알림을 띄운다.
- 이미 제출된 신고서에 영향을 주는 출결 수정은 저장 전에 경고한다.

### 6.3 통계
학생별 kind × category 건수를 학년도 누적으로 보여주고, 월·학급 필터를 지원한다. 결석은 건수와 수업일 일수를 함께 표시한다.

### 6.4 hwpx 양식 갱신(자리표시자 방식, 학교별 범용)
- 결석신고서는 **자리표시자 양식**으로 만든다. 사용자는 한글에서 학교 양식의 내용 자리에 `{{이름}}`, `{{학번}}`, `{{시작월}}` 같은 표시를 써서 올린다. 체크 칸은 `{{결석_질병}}` 같은 표시가 ■/□로, 증빙 표의 확인 칸은 `{{증빙_3일이상}}` 같은 표시가 ○/빈칸으로 바뀐다. 전체 목록은 설정 화면과 "자리표시자 안내" 파일로 제공한다.
- 한글이 표시 하나를 여러 조각으로 저장해도 같은 문단 안이면 이어 붙여 인식한다.
- 사용자가 제공한 학교 양식에 미리 자리표시자를 넣어 **기본 양식**으로 내장한다(문서 속성의 사람 이름 제거).
- 올린 양식을 검사해 찾은 표시와 알 수 없는 표시(오타)를 보여준다. `{{이름}}`과 `{{학번}}`이 모두 없으면 거부한다. 통과하면 새 버전으로 저장·활성화하고, 이전 버전·기본 양식으로 되돌릴 수 있다. 기본 양식은 내려받아 고쳐 쓸 수 있다.
- 여러 명을 한 파일로 만들 때는 양식 본문 전체를 학생마다 복제해 쪽을 나눈다(개체 id는 겹치지 않게 바꾼다). 학생별 파일 ZIP도 지원한다.

### 6.5 누가기록 정리
- 입력: 상담일지의 날짜별 행에 개조식 메모 또는 녹취 텍스트를 넣는다.
- 처리: 사용자가 "누가기록으로 정리"를 누르면 학생 이름을 가명으로 치환해 AI에 보내고, 설정에서 편집할 수 있는 **누가기록 프롬프트**(6.9절)와 **최대 글자 수**(`nuga_max_chars`)에 맞춰 정리된 문장을 받는다. 응답에서 이름을 되돌린다.
- 기본 프롬프트는 객관적 사실 중심의 서술, 추측·평가 표현 자제, 날짜별 단락이며, 사용자가 제공하는 샘플과 문체 규칙으로 설정에서 직접 고친다.
- 출력: `nuga_text`에 저장(직접 수정 가능), "복사" 버튼으로 나이스에 붙여넣는다. 나이스에 입력한 뒤 `나이스 입력 완료`로 표시하면 목록에서 미입력 건만 볼 수 있다.
- 정리본이 최대 글자 수를 넘으면 경고하고 줄여 달라고 다시 요청할 수 있다.
- 원문(`content`)은 항상 보존한다.
- **정리본의 표시 형식은 앱이 만든다:** `YYYY.MM.DD.(요일) | 장소` 한 줄 + 내용 한 단락. 요일은 코드로 계산하고(AI에 맡기지 않음), AI는 내용 문장만 만든다. AI 응답은 건별 구조(id, 내용)로 받는다.
- **분량:** 문장 수·글자 수를 고정하지 않고 메모의 정보량에 비례하게 쓴다(부록 B). `nuga_max_chars`는 선택적 상한 경고로만 쓴다.
- **이름 처리:** 전송 전 명단 학생 이름을 가명으로 치환하고, 결과에서 실명으로 되돌린 뒤 **조사(은/는, 이/가, 을/를, 와/과, 으로/로)를 자동 보정**한다. 대상 학생 본인 이름은 쓰지 않는다(지시문 + 코드 검사). 명단에 없는 다른 반 학생 이름은 가려지지 않으므로 설정 화면에 안내한다.
- **결과 검사(경고만, 자동 수정 없음):** 대상 학생 이름·가명 잔존, 진단 용어 목록(ADHD, 우울 등) 포함, 최대 글자 수 초과, 원문에 없는 숫자·날짜 등장.

### 6.6 자리배치표
- 학급마다 열×행을 직접 정한다(예: 5×5). 각 칸은 학생 / 빈자리 / 책상 없음 중 하나.
- 끌어다 놓기: 명단에서 칸으로 배치, 칸끼리 끌면 맞바꿈, 빈자리로 끌면 이동, 칸에서 명단으로 끌면 배치 해제. 키보드(방향키 + 선택)로도 이동 가능.
- 고정석(`fixed`)은 무작위 배정에서 제외. 무작위 배정은 고정석과 책상 없음 칸을 뺀 칸에 남은 학생을 무작위로 채운다.
- 이전 배치를 복사해 새 배치를 만들 수 있고, 날짜별 이력을 남긴다.
- **출력(사용자 제공 예시 양식 기준):** A4 가로. 상단 가운데 제목 `{학년}학년 {반}반 자리배치표({월}월)`(수정 가능). 책상마다 테두리 상자에 큰 굵은 글씨로 `번호.이름`, 책상 사이 간격. 빈자리는 빈 상자, 책상 없음 칸은 상자를 그리지 않는다. 교탁 상자는 아래 가운데(기본, 위로 바꿀 수 있음). 오른쪽에 반·번호·이름 소형 명렬표(켜고 끄기).
- 학생 수가 사용 가능한 칸보다 많으면 경고한다.

### 6.7 청소배치표
- **기본 구역 목록 없이 빈 표로 시작하는 자유 표.** 행(구역)과 열(칸)을 모두 사용자가 추가·삭제·이름 변경·순서 변경한다. 기본 열은 `구역 | 담당 학생 | 비고` 세 개이며 이것도 고칠 수 있다.
- 열 종류는 두 가지: 글자 칸(자유 입력)과 학생 칸(학생을 끌어다 넣는 칸, 여러 명 가능). 학생 칸 열은 하나 이상 둘 수 있다(예: 1주차·2주차).
- 명단에서 학생을 끌어 학생 칸에 넣고, 칸끼리 끌어 옮기거나 칸에서 명단으로 끌어 빼낸다. 미배정 학생은 명단에 따로 표시한다.
- "자동 분배"로 미배정 학생을 학생 칸에 고르게 나눌 수 있다(선택 기능).
- "순환" 버튼으로 담당을 한 구역씩 밀어 주간 교대를 한다.
- 출력: A4, 구역별 명단 표.

### 6.8 명렬표
기존 엑셀의 학급명렬표 기능을 대체한다. 학급 선택, 표 제목, 번호·이름 외에 빈 열 개수(체크·서명용), 글자 크기를 정하고 hwpx 내보내기(기본), A4 인쇄, 엑셀 내보내기.

### 6.10 hwpx 내보내기 공통
- 대상: 결석신고서(양식 채우기), 명렬표, 자리배치표, 청소배치표, 상담일지(학생별·기간별), 통계표(표 생성).
- 각 화면의 "hwpx로 내보내기"가 기본 버튼이고, A4 인쇄·PDF와 엑셀(표 형태 문서만)은 보조 버튼이다.
- 표 생성 문서는 행·열 수에 맞춰 칸 너비·높이와 글자 크기를 자동 계산해 한 쪽(A4)에 맞춘다. 넘치면 쪽을 나누고, 자리배치표처럼 한 쪽이어야 하는 문서는 글자 크기를 줄인 뒤 그래도 넘치면 경고한다.
- 한글에서 열었을 때 그대로 편집할 수 있도록 표는 실제 한글 표로 만든다(그림 아님).
- 결석신고서는 사용자가 양식을 교체할 수 있다(6.4절). 표 생성 문서의 기본 양식 교체는 1단계 범위 밖이며, 제목·글자 크기 같은 옵션만 화면에서 고친다.

### 6.9 AI 프롬프트 편집
- 설정 > AI 프롬프트에서 **누가기록 정리**와 **전달사항(조·종례) 정리** 두 가지 지시문을 편집한다.
- **지시문(사용자 편집 영역)과 출력 형식(앱 고정 영역)을 분리한다.** 앱이 지시문 뒤에 출력 형식(앱이 읽을 수 있는 구조)을 자동으로 덧붙여, 지시문을 어떻게 고쳐도 화면이 깨지지 않는다.
- 지시문에서 쓸 수 있는 자리표시자: `{최대글자수}`, `{날짜}`. 날짜·장소·메모는 자리표시자가 아니라 앱이 구조화된 입력으로 따로 전달한다.
- 사용자 지시문에는 작성 규칙과 예시만 둔다. "출력 형식" 절은 앱 고정 영역이라 지시문에 있어도 앱이 정한 형식이 우선한다.
- 기본 프롬프트를 제공하고 "기본값으로 되돌리기"와 최근 5개 버전 복원을 지원한다. "샘플로 시험" 버튼으로 샘플 입력에 대한 결과를 미리 볼 수 있다(호출은 사용자가 누를 때만).
- 지시문에는 실제 학생 이름을 쓰지 않도록 안내한다(가명 치환은 입력 데이터에만 적용된다).
- 프롬프트는 백업에 포함한다(키는 제외).

## 7. 화면

노트북 기준 왼쪽 메뉴: `홈 / 출결 / 상담일지 / 학급 / 결석신고서 / 통계 / 설정`. 화면 폭이 좁아지면 하단 탭으로 바뀌게 반응형으로 만들어 2단계의 폰 지원에 대비한다.

1. **홈:** 오늘 학사일정(수업일 여부·행사), 오늘 급식(알레르기 표기 포함), 내 시간표, 조례/종례 탭(AI 정리 체크리스트, 편집, 전달 완료 체크), 입력창(붙여넣기·이미지·메모, "정리" 버튼), 맨 아래 앞으로 2주 학사일정(D-day).
2. **출결:** 학급·날짜(기본 오늘). 번호순 학생 목록, 기본 출석. 학생 선택 → 구분, 종류, (지각·조퇴·결과일 때) 교시, 사유, (출석인정일 때) 증빙 구분. 저장하면 "신고서" 뱃지. 키보드 중심 빠른 입력.
3. **학급:** 상단 탭 `명단 / 명렬표 / 자리배치 / 청소배치`. 명단은 번호·이름·보호자 성함·번호 표와 엑셀 붙여넣기 일괄 등록, 학생 상세 편집.
4. **상담일지:** 학급 → 학생 선택, 인적사항 요약, 날짜·원문·누가기록 정리본 목록, 추가·수정, "누가기록으로 정리", "복사", 나이스 입력 완료 체크와 미입력 필터, 전체 키워드 검색, 인쇄, 엑셀 내보내기.
5. **결석신고서:** 월 선택, 목록(학생, 기간, 수업일 수, 증빙, 진단서 필요/수령, 제출), 미제출 필터, 선택 건 hwpx 한 파일 또는 학생별 ZIP, 일괄 제출 체크.
6. **통계:** 학생별 누적 표, 학급·월 필터, 엑셀 내보내기.
7. **설정:** 담임 성명, 학교·NEIS 키와 코드, 학사일정·급식·시간표 새로고침, 내 시간표(담당 과목·수업 학급 선택 → 자동 추정 → 수동 수정), hwpx 양식 갱신, 백업 폴더·암호구·지금 백업·복원, PIN 잠금, AI 키·스위치·이름 가리기, AI 프롬프트 편집(누가기록·전달사항), 누가기록 최대 글자 수.

## 8. NEIS 연동
- 교육정보 개방 포털의 인증키를 사용자가 발급받아 설정에 넣는다. 교육청 코드와 학교 코드를 학교 검색으로 선택한다.
- 가져오는 정보: 학사일정, 급식식단(알레르기 번호 포함), 학교 전체 학급의 시간표(담임 학급 표시와 내 시간표 추정에 사용). 가져온 값은 `neis_cache`에 저장해 오프라인에서도 보인다.
- **내 시간표 추정(반자동):** ① 설정에 담당 과목명(복수 가능)과 수업하는 학급을 고른다. ② 앱이 NEIS 전체 학급 시간표에서 해당 학급의 해당 과목 칸을 모아 요일·교시별 내 시간표 초안을 만든다. ③ 사용자가 칸을 고쳐 확정한다(`source=manual`로 표시되어 재추정 때 덮어쓰지 않음). 학기가 바뀌거나 시간표가 변경되면 "다시 추정" 버튼을 쓴다.
- **한계:** 조사한 NEIS 문서에서는 시간표 응답에 수업 내용(`ITRT_CNTNT`, 과목명)만 확인되고 교사 이름 필드는 찾지 못했다. 교사 정보가 없으면 과목명 일치로만 추정하므로, 같은 학급에서 같은 과목을 여러 교사가 나눠 가르치거나 과목 표기가 다르면(선택과목 등) 틀릴 수 있다. 구현 초기에 실제 응답으로 확인하고, 교사 필드가 있으면 이름 일치로 정확하게 만든다.
- 직접 입력한 일정은 가져오기로 덮어쓰지 않는다.
- 브라우저에서 직접 호출이 허용되는지(CORS)를 구현 초기에 실측한다. 막혀도 exe에서는 앱의 네트워크 계층으로 호출하므로 영향이 없다(웹 개발·검증 단계에서만 해당).

## 9. AI 기능

공통: 사용자가 버튼을 눌렀을 때만 호출. 학생 이름은 명단 기준으로 가명 치환 후 전송하고 응답에서 되돌린다. 이미지 입력에는 다른 정보가 함께 찍힐 수 있다는 경고를 보인다. 키는 기기 저장소에만 있으며 개인 노트북 1대 전제의 방식이다. Console에서 지출 한도를 걸도록 안내한다. 작은 모델과 입력 길이 제한을 쓴다. 실패·한도 초과·키 오류 시 원문을 보여주고 수동 편집이 가능하다.

1. **오늘의 전달사항(홈):** 학교 메신저·공문에서 복사한 텍스트, 캡처 이미지, 직접 메모 → 조례용·종례용 체크리스트(말할 순서, 한 문장씩). 결과는 `briefings`에 저장되고 편집 가능.
2. **누가기록 정리(상담일지):** 6.5절.

두 기능의 지시문(프롬프트)은 설정에서 편집할 수 있다(6.9절).

후속(범위 밖): 학생별 누적 상담 요약, 결석 사유 문구 정리, 월말 안내문 초안.

## 10. 보안·개인정보 요약
- 학생 데이터는 노트북 안에만 저장. 외부로 나가는 것은 사용자가 누른 AI 정리의 이름 가린 텍스트뿐(전달사항, 누가기록 원문).
- 백업은 항상 암호화. 키는 백업에서 제외.
- PIN 잠금은 선택 사항이며 화면 접근 통제용.
- 전달사항과 상담 원문에 이름 외의 식별 정보(주소, 연락처 등)가 있으면 가려지지 않으므로, 전송 전에 학번·전화번호 형태를 추가로 가리는 규칙을 둔다(번호 패턴 치환).

## 11. 오류 처리
- 저장 실패(저장 공간 부족, 브라우저 오류): 입력을 화면에 보존하고 즉시 알림, 백업 권유.
- 백업 폴더 권한 상실·폴더 삭제: 시작 시 알림 후 재지정.
- 백업 복원: 복원 전 현재 상태를 자동으로 한 번 더 암호화 백업한 뒤 덮어쓴다. 잘못된 암호구·변조 파일은 명확한 메시지로 거부. 스키마 버전이 다르면 마이그레이션하거나 거부.
- AI·NEIS 실패: 캐시된 값이나 원문을 보여주고 수동으로 계속 가능.
- 중복 입력(학생·날짜·구분): 기존 행을 열어 수정으로 유도.
- 학사일정 누락: 평일 기준으로 계산하고 "학사일정 미등록" 경고.
- 양식 검사 실패: 기존 양식 유지, 맞지 않는 위치 안내.
- 자리배치·청소배치: 학생 전학·삭제 시 배치에서 빠진 칸을 빈칸으로 표시, 학생 수가 칸 수보다 많으면 경고.

## 12. 테스트
- **단위(Vitest):** 수업일 계산, 신고서 병합·분할·증빙 판정(2일→3일 전환), 통계, 이름 가리기/복원(전화번호 패턴 포함), 백업 암복호화 왕복·잘못된 암호구·변조 탐지, 스키마 마이그레이션, 자리 무작위 배정(고정석·사용 안 함 칸 제약), 청소 구역 자동 분배·순환, 누가기록 글자 수 검사, 프롬프트 조립(사용자 지시문 + 고정 출력 형식, 기본값 복원), 요일 계산, 가명 복원 후 조사 보정, 누가기록 결과 검사(이름 잔존·진단 용어), 전체 시간표에서 내 시간표 추정.
- **hwpx:** 제공된 생성기 출력과 이식 모듈 출력을 같은 입력으로 비교하는 골든 파일 테스트, 양식 검사 통과/실패. 표 생성 문서는 파일 구조 검사(mimetype 첫 항목·비압축, XML 유효성, 표 행·열 수, 셀 주소·병합 일관성)와 다양한 크기(5×5, 6×6, 학생 35명 명렬표 등)의 자동 생성 테스트.
- **한글 실제 열기 확인(사용자):** 개발 환경에는 한글 프로그램이 없어 각 문서 종류의 첫 결과물은 사용자가 한글에서 열어 확인한다. 이 확인을 문서 종류마다 해당 단계의 완료 조건으로 둔다.
- **E2E(Playwright):** 출결 입력 → 신고서 생성 → 제출 체크, 오프라인 동작, 백업 후 데이터 삭제 → 복원, 홈 정리와 누가기록 정리(AI는 모의 응답), 자리배치 끌어다 놓기·출력 미리보기(예시 양식과 비교), PIN 잠금(시작 시·절전 복귀 시).
- **수동 확인:** 크롬 설치형 앱, 자동 백업 폴더 권한 흐름, NEIS 호출(CORS), A4 인쇄 결과.

## 13. 확인이 필요한 항목
1. 나이스 누가기록의 글자(바이트) 수 제한 여부. 누가기록 양식·프롬프트는 제공받은 문서를 검토해 부록 B에 반영했다.
2. NEIS: 인증키 발급 완료. 키는 앱 설정 화면에만 입력하고 대화창에는 붙여넣지 않는다. 교육청·학교 코드는 앱의 학교 검색으로 고른다. 시간표 응답에 교사 필드가 있는지는 구현 3단계에서 노트북에서 실측한다(개발 환경에서는 NEIS 서버 접속이 막혀 있음).
3. (확정) 모든 출력물은 hwpx 내보내기가 기본. 청소 구역은 기본 목록 없이 자유 표.
4. 내 시간표 추정에 쓸 담당 과목명과 수업 학급. NEIS 시간표 응답에 교사 필드가 있는지는 구현 초기에 확인.
5. (확정) Windows용 포터블 exe. 서명되지 않은 exe라 첫 실행 때 뜨는 보안 경고는 "추가 정보 → 실행"으로 허용한다.
6. 백업 보관 개수(기본 14개로 시작).

## 14. 구현 순서(개요)
이 범위는 한 번에 만들기에 크므로 단계마다 별도 구현 계획서로 나누어 진행한다.

1. 프로젝트 골격, `lib/db`, 레코드 모델, 암호화 백업·복원
2. 학급·학생(엑셀 붙여넣기 등록) + `lib/hwpx/build` 기반 구축 + 명렬표 hwpx 출력
3. NEIS 연동(학사일정·급식·전체 학급 시간표, 응답 필드 확인 포함)과 수업일 계산, 내 시간표 추정
4. 출결 입력 + 신고서 자동 생성 + hwpx 이식·양식 갱신
5. 결석신고서 목록·제출 체크
6. 상담일지 + 누가기록 AI 정리 + AI 프롬프트 편집(설정)
7. 통계
8. 자리배치표·청소배치표 + hwpx 출력·인쇄
9. 홈(전달사항 AI, 일정·급식·시간표 표시)
10. PIN 잠금, Electron 포터블 exe 포장, 마무리

## 부록 B. 기본 누가기록 프롬프트(사용자 지시문 영역)

외부 검토 문서를 기준으로 하되, 예시에서 메모에 없는 내용이 들어간 부분(시점, 칭찬 대상, 준비 여부, "일반" 대학, 누락된 학교 종류)을 고쳤다. 앱은 이 지시문 뒤에 구조화된 입력(건별 id, 날짜, 장소, 메모)과 출력 구조(건별 id, 내용)를 덧붙인다.

```
# 역할
너는 초·중·고 담임교사의 학생 누가기록 작성을 돕는 도우미야.

# 작성 규칙
- 분량은 정해두지 않고 입력된 메모의 정보량에 맞춘다. 메모가 짧으면 1문장으로 짧게 쓰고, 내용이 많으면 누락 없이 여러 문장으로 자연스럽게 쓴다.
- 문장 종결은 "~함", "~했음" 체로 쓴다.
- 관찰한 행동과 학생의 말을 사실대로 쓰고, 성격·상태를 단정하는 표현은 쓰지 않는다. 메모에 "소극적이다" 같은 단정 표현이 있으면 쓰지 않고 관찰된 행동만 남긴다.
- 학생의 말은 핵심만 짧게 따옴표로 인용한다.
- 교사의 지도·대화 내용이 메모에 있으면 마지막 문장으로 정리한다.
- 메모에 있는 구체적 정보(진로 희망, 학교·학과 종류, 과목, 장소 등)는 빠뜨리지 않는다.
- 메모에 없는 내용은 절대 추가하지 않는다. 시점, 이유, 배경, 칭찬의 대상, 준비 여부 등을 추측해서 덧붙이지 않고, 메모의 표현 범위 안에서만 쓴다.
- 진단적 표현(ADHD, 우울 등)은 쓰지 않는다.
- 기록 대상 학생 본인의 이름(주어)은 쓰지 않는다. 메모에 나오는 다른 사람의 이름은 입력에 적힌 그대로 유지한다.

# 예시 (입력 → 출력 내용)
입력: 점심시간 교실 / 민수랑 말다툼하고 혼자 밥 먹음. 이유 물으니 말 오해해서 서운했다고 함. 대화로 풀어보라고 함.
출력: 민수와 말다툼 후 혼자 앉아 식사함. 교사가 이유를 묻자 "말을 오해해서 서운했다"고 답함. 교사가 대화로 풀어 보도록 안내함.

입력: 수학 시간 교실 / 모둠 문제풀이에서 못 푸는 친구한테 풀이 설명해줌. 전엔 수학 싫다고 했는데 적극적. 수업 후 칭찬함.
출력: 모둠 문제풀이에서 어려워하는 친구에게 풀이를 설명해 줌. 이전에 수학이 싫다고 말했으나 이번에는 적극적인 모습을 보임. 교사가 수업 후 칭찬함.

입력: 상담실 / 요리 관심 있는데 부모님은 대학 진학 원하시며 반대. 자기는 조리특성화고나 관련 학과 가고 싶다고 고민 털어놓음. 이야기 들어주고 조리 관련 진로 정보랑 학과 안내해줌. 부모님과도 대화해보기로 함.
출력: 요리에 관심이 있으나 부모님이 대학 진학을 원하며 반대하셔서 고민이라고 말함. 조리특성화고나 관련 학과에 가고 싶다는 뜻을 밝힘. 교사가 이야기를 들어 주고 조리 관련 진로 정보와 학과를 안내함. 부모님과도 대화해 보기로 함.

입력: 청소시간 교실 / 맡은 구역 청소 끝내고 다른 모둠 도와줌. 시키지 않았는데 먼저 함.
출력: 맡은 구역 청소를 마친 뒤 교사의 지시 없이도 다른 모둠의 청소를 먼저 나서서 도움.

입력: 국어 시간 교실 / 발표 시키니까 목소리 작아지고 얼굴 빨개짐. 소극적인 아이. 끝까지는 함. 격려해줌.
출력: 발표를 시키자 목소리가 작아지고 얼굴이 붉어졌으나 끝까지 발표함. 교사가 격려함.
```

운영 안내(프롬프트가 아닌 설정 화면 도움말): 기록은 키워드만이라도 그날 메모하기, 조용한 학생이 누락되지 않게 학생당 월 1~2건 이상 고르게 기록하기, 학기 말에 행동특성 및 종합의견 근거로 훑어보기, 강점과 긍정적 변화도 관찰되면 기록하기(프롬프트에는 넣지 않음).

## 부록 A. 2단계(보류): 폰 연동과 암호화 동기화

1단계의 `lib/db`와 레코드 규칙을 그대로 두고 동기화 층만 추가한다.

- **서버:** Supabase(서울 리전, Auth + Postgres). 서버 표는 암호화된 레코드(`sync_records`)와 키 보관 정보(`vaults`)뿐이며 서버는 평문을 보지 못한다.
- **키 구조:** 기기에서 무작위 데이터 키(DEK, AES-256) 생성. DEK는 ① 암호구에서 유도한 키(PBKDF2-SHA256, 반복 600,000회 이상, 무작위 salt)와 ② 한 번만 보여주는 복구 키(무작위 256비트) 두 가지로 감싸 서버에 둔다. 암호구와 복구 키를 모두 잃으면 서버 데이터는 복구 불가.
- **동기화:** 바뀐 레코드를 레코드별 IV로 AES-GCM 암호화해 올리고 서버가 단조 증가 `server_version`을 부여. 마지막으로 받은 버전 이후를 당겨 복호화·병합. 충돌은 나중에 수정한 쪽 우선, 삭제는 tombstone, 복호화 실패 레코드는 병합하지 않고 오류 목록에 남김.
- **AI:** 이때 API 키를 서버(Edge Function) 비밀값으로 옮기고 호출 한도를 서버에서 통제한다.
- **로그인:** 단일 계정, 회원가입 비활성화.
- **테스트:** 암복호화 왕복과 변조 탐지, 키 감싸기, 동기화 병합, RLS, 두 가상 기기 간 동기화.
