# 설계서 2 — Watson 명령 입력과 새 홈

상태: 검토 대기 · 근거: 문서 '홈 개편 기획안'(11/10 확정) · 설계서 1(앱 틀) 다음에 만든다

## 1. 목표와 성공 기준
- 홈의 입력 막대 하나에서 /명령 @학생 #태그로 기록·조회·정리를 끝낸다. 다른 화면에서는 W 버튼(Ctrl+K)으로 같은 입력을 연다.
- 규칙으로 되는 일은 노트북 안에서 바로(AI·인터넷 없이), 글을 다듬거나 문장을 알아들을 때만 AI.
- 성공 기준: ① '/출결 @3 결석 질병 감기' 입력부터 저장까지 키보드만으로 10초 안 ② 자동완성 첫 화면 0.1초 안(학생 40명·명령 15개) ③ AI가 꺼져도 규칙 명령 모두 동작 ④ 어떤 실행도 대화 기록에 남고 링크로 그 화면에 간다.

## 2. 화면
### 홈
- 제목 줄: 날짜·수업일, 그 아래 한 줄 요약(오늘 출결 · 지금 교시 · 급식). 누르면 펼침.
- 가운데: 대화 기록(위) + 입력 막대(아래 고정). 내 입력은 오른쪽 말풍선, 결과는 왼쪽 카드(규칙/AI 표시, 링크, 되돌리기, ⋯메뉴: 다시 실행·지우기).
- 오른쪽 패널(펼친 채, 접기 가능): 할 일(체크) · 다가오는 일정(날짜별, 개인·업무·학사 태그 색) · 노트함(전달사항·메모).
- 대화 영역 높이·오른쪽 패널 폭은 끌어서 조절, 기기에 기억(localStorage).
- 색은 모두 테마 토큰을 쓴다(어둡게 포함).
### 다른 화면
- 오른쪽 아래 동그란 **W** 버튼. 누르면 왼쪽으로 늘어나 입력 막대(너비 최대 640px)가 되고, 자동완성·결과 카드는 막대 위로 뜬다. Esc·바깥 클릭이면 다시 W. Ctrl+K도 같다.
- 실행은 홈 대화 기록에도 남는다.

## 3. 입력 문법 (규칙 해석기 `src/lib/command/parse.ts`)
- 토큰: `/명령`(세부 명령은 띄어쓰기, `_`도 같은 뜻), `@학생`(이름·번호·초성), `#태그`, 나머지 낱말.
- 규칙 사전(`src/lib/command/lexicon.ts`):
  - 출결 종류: 결석·지각·조퇴·결과 / 구분: 미인정·질병·출석인정(인정)·기타
  - 교시: 3교시, 5~7교시, 5-7교시
  - 날짜(`dates.ts`): 오늘·내일·모레·어제·그제, 11/12·11.12·12일, (다음주|이번주) 요일, 요일, 시각 15:30·오후 3시 반
  - 일정 태그: #개인 #업무 (학사는 나이스에서만)
- 남은 낱말은 명령마다 사유·내용·제목이 된다.
- 해석 결과는 입력하는 동안 막대 아래 한 줄로 보인다('3번 박도윤 · 11/9 · 결석(질병) · 사유: 감기').
- 초성 검색은 `src/lib/hangul.ts`(완성형 음절 → 초성).

## 4. 자동완성 (`suggest.ts`)
- 커서 앞 토큰 종류로 후보를 고른다: `/`→명령(세부 명령 2단), `@`→학생(번호·이름·초성, 최대 8), `#`→그 명령의 태그, 그 밖→그 명령이 기대하는 낱말(예: 결석 다음엔 미인정·질병·출석인정).
- ↑↓ 고르기, Enter·Tab 넣기, 목록이 없을 때 Enter 실행, Esc 닫기, 빈 칸에서 ↑ 직전 입력. 마우스 클릭도 같다.
- 한글 조합 중(isComposing)에는 Enter를 넣기·실행으로 쓰지 않는다.

## 5. 명령 (`registry.ts`: id · 이름·별칭 · 그룹 · 처리(rule|hybrid|ai) · 인자 · preview() · run())
| 단계 | 명령 | 처리 | 결과 |
|---|---|---|---|
| 1 | /출결 | 규칙 | 저장(+신고서 자동) · 링크: 출결(그날·그 학생) |
| 1 | /상담기록 | 규칙 | 상담 기록 저장 · 링크 |
| 1 | /정보 | 규칙 | 학생 카드(연락처·보호자·최근 출결·상담) |
| 1 | /일정 달력 · /일정 할일(=/할일) | 규칙 | 일정 저장(구글 연결 시 앱 캘린더로) / 할 일 추가 |
| 1 | /찾기 | 규칙 | 출결·상담·일정·노트 통합 검색 |
| 2 | /자리 #조건 | 규칙 | 자리 미리보기 → 적용(조건은 새 기능 단계에서 확장) |
| 2 | /신고서 @학생 | 규칙 | 그 학생 최근 신고서 hwpx |
| 2 | /전달 학생 | 규칙 | 노트함 전달사항에 추가 |
| 2 | /내보내기 화면 형식 | 규칙 | 설계서 1의 내보내기 호출 |
| 3 | /상담정리 @학생 | AI(이름 가림) | 누가기록 초안 → 저장 |
| 3 | /전달 학부모·교사 | 하이브리드 | 문자·메신저 문장 초안 + 복사 |
| 3 | (긴 붙여넣기) | AI | 전달사항으로 나눔 → 카드에서 '전달사항에 추가' |
| 3 | (/ 없는 문장) | AI | 명령 한 줄로 바꿔 '이렇게 실행할까요?' → 확인해야 실행 |
| 새 기능 | /반성문 | AI | 반성문 창 |

- 실행 규칙: 인자가 다 있으면 바로 저장하고 결과 카드에 10초 '되돌리기'. 빠졌거나 학생이 여럿 맞으면 결과 창(떠 있는 창)에서 채운다. 제출된 신고서에 영향이 있으면 지금처럼 먼저 묻는다.
- 되돌리기는 run()이 돌려준 undo 함수(이번 실행 안에서만, 10초).

## 6. 자료 (DB v3, 백업 포함)
- `chat_log`: id, at, school_year, input, mode(rule|hybrid|ai), result{summary, links[{label,to}], status}, deleted. 지우기·'오늘 대화 지우기', 새 학년도(3/1)에 지난 학년도 자동 삭제.
- `todos`: id, title, due?, done, done_at?, order.
- `notes`(노트함): id, kind('전달'|'메모'), text, date, done, order. **조례·종례 합치기**: 기존 briefings의 항목을 notes(kind '전달', 같은 날짜)로 옮기고 briefings는 읽기 전용으로 남긴다(백업 호환).
- `local_events`(내 일정): id, date, end_date?, time?, title, tag('개인'|'업무'), google_id?. 구글 연결 시 기존 앱 캘린더 동기화에 태운다.
- 모두 SYNCED_TABLES에 넣어 암호화 백업에 포함. 백업 형식 번호는 그대로(없는 표는 빈 것으로 복원).

## 7. 부품 구성
- `src/lib/command/` parse · lexicon · dates · suggest · registry · run(실행+기록+undo)
- `src/components/command/` CommandBar(입력+자동완성+해석 미리보기) · ChatLog · ResultCard · FloatingPanel · WButton
- `src/pages/home/` HomePage(새 배치) · RightPanel(Todos · Upcoming · Notebox) · TodaySummary
- 기존 화면 부품(출결 입력, 상담 새 기록)을 떠 있는 창 안에서 다시 쓴다.

## 8. AI
- 하이브리드·AI 명령은 기존 `createRoutedAiCaller`와 이름 가림을 그대로 쓴다. 결과 카드에 'AI' 표시.
- 문장 해석 프롬프트는 명령 목록과 문법만 주고 JSON `{command: "/..."}`만 받는다. 받은 줄은 다시 규칙 해석기로 미리보기를 만든 뒤 사용자 확인 후 실행. AI는 저장을 직접 하지 않는다.

## 9. 오류 처리
- 해석 실패: 막대 아래 빨간 한 줄('학생을 찾지 못했습니다 · @를 눌러 고르세요'), 실행 안 함.
- AI 꺼짐·실패: 카드에 이유 + 설정 > AI 링크. 규칙 명령은 영향 없음.
- 저장 실패: 카드에 오류, 기록은 status '실패'로 남김.

## 10. 시험
- 단위(TDD): 날짜 사전(기준일 고정), 출결 사전, 초성, 토큰 해석, 자동완성 후보, 명령별 preview/run/undo, 브리핑→노트 옮기기, 학년도 정리.
- 화면: 홈·W 막대·자동완성·결과 카드 캡처(기본·어둡게), 키보드만으로 /출결 시나리오(Playwright).

## 11. 하지 않는 것(이번 설계)
- 음성 입력, 여러 명령 한 줄에, 반성문·자리 조건 세부(새 기능 단계에서).
