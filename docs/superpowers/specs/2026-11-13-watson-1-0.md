- 사용자 결정(11/13): 학생 자료 **전체 암호화**, 드라이브는 **PC 여러 대 자동 동기화**, 개인 Gmail, 내 드라이브에 보이는 'Watson' 폴더(`drive.file`), 구글 프로젝트는 '프로덕션', 다른 선생님께 소수 배포, HTML판 폐지.

## 0. 목표와 하지 않는 것

**목표**
1. 노트북 도난·디스크 복사로 학생 자료가 읽히지 않는다.
2. 학교 PC와 집 PC가 같은 자료를 본다. 드라이브에는 암호문만 있다.
3. 구글 연결이 깔끔하다(경고 화면 없이 시작, 캘린더는 따로).
4. exe 쪽 보안 구멍(보안 점검)을 막는다.
5. 무엇이 실패해도 자료를 잃지 않는다. 늘 되돌아갈 백업이 있다.

**하지 않는 것(1.0)**: 휴대폰 앱, 한글 문서 작성(rhwp), 코드 서명 인증서, 필드 단위 설정 병합, 실시간(초 단위) 동기화, 여러 사람(교사 간) 공유.

**위협 모델**: 잠기지 않은 채 켜 둔 PC에서의 열람은 막지 않는다(그건 PIN·Windows 잠금의 몫). 같은 윈도우 계정으로 도는 악성 프로그램도 막지 못한다(DPAPI 한계, §10).

## 1. 출시 단계

새 exe는 한 번만 낸다(SHELL 7). 그 exe 안에 메인 쪽 기능을 모두 넣는다. 화면(렌더러) 기능은 위험이 작은 순서로 나눠 낸다.

| 판 | exe | 담는 것 | 관문(다음으로 넘어가는 조건) |
| --- | --- | --- | --- |
| 1.0.0 | SHELL 7 새 exe | 메인 기능 전부(§3~§8의 메인 쪽) + 렌더러: 암호화·옮기기·자료 열기, 구글 계정 탭(구글로 시작·캘린더 연결), 자동 실행·바로가기, 닫기 전 저장, 업데이트 되돌리기 | 선생님 PC에서 옮기기·열기·백업·복원 확인, 1주 사용 |
| 1.0.x | 그대로 | 드라이브 동기화(§6) | 두 PC 동기화 시험(§9 시나리오) |

옛 exe(SHELL ≤6)에는 '새 exe를 받으세요'만 간다. 그들은 0.18에 머문다.

## 2. 시작 순서(exe)

```
렌더러 시작
 └ vault:status (메인)
    ├ none         → 처음 1.0: §4 옮기기 마법사
    ├ ok           → 메인이 DPAPI로 DEK를 풀어 넘김 → DB 열기(암호화 미들웨어) → PIN 잠금(있으면) → 앱
    ├ needs-pass   → '자료 열기' 화면: 백업 암호구로 DEK 풀기 → 메인이 DPAPI로 다시 감싸 저장 → 위와 같음
    └ broken       → '자료 열쇠 파일이 손상됨' 화면: 암호구로 열기 / 백업 파일에서 복원
웹(개발·캡처) 환경: vault 없음 → 지금처럼 평문 DB 'class-manager'
```
- 렌더러는 DB를 열기 전까지 아무 자료 화면도 그리지 않는다(앱 틀만).
- 앱이 첫 화면을 그리고 DB가 열리면 `app:ready`를 보낸다(§8.1 되돌리기 판정).

## 3. 열쇠(vault)

**DEK(자료 열쇠)**: 무작위 32바이트, `keyId`(uuid)와 짝. DEK는 렌더러 메모리에만 평문으로 있다.

**보관 파일**: 메인이 `%APPDATA%\Watson\vault.json`에 둔다(쓸 때 임시 파일 → 이름 바꾸기, 직전 판 `vault.json.bak` 보관).
```json
{ "v": 1, "keyId": "…", "dbName": "watson-1",
  "dpapi": "<safeStorage 비동기 encryptStringAsync(base64 DEK) 결과 base64>",
  "pass": { "salt": "b64", "iter": 600000, "iv": "b64", "ct": "b64(AES-GCM(passKey, DEK, aad='watson-dek:'+keyId))" } }
```
- `passKey` = PBKDF2-SHA256(백업 암호구, salt, 600k) → AES-256-GCM 열쇠. **백업 파일 열쇠와 같은 것**이다(같은 salt를 쓴다). 암호구 하나로 백업·자료 열쇠·드라이브가 모두 열린다.
- `pass`는 백업 암호구가 있을 때만 있다.
- safeStorage는 **비동기 API**(Electron 44에 있음, 동기 API는 46에서 제거 예정)를 쓴다. `shouldReEncrypt`가 오면 다시 감싸 저장한다.
- DPAPI 풀기가 실패하는 경우: 다른 PC·다른 윈도우 계정, 관리자가 윈도우 암호를 재설정, `Local State`가 지워짐(§10). 이때 `needs-pass`.

**백업 열쇠 캐시 바꾸기**: 지금은 `device_local.backupKey`에 꺼낼 수 없는 CryptoKey를 둔다. 브라우저가 이를 디스크에 원시 바이트로 쓰므로(보안 점검 H2) 1.0에서 없앤다. 대신 꺼낼 수 있게 만든 `passKey` 원시 바이트를 **암호화된** `device_local.backupKeyRaw`에 둔다(DEK로 보호). 그래서 옮길 때 암호구를 한 번 받아야 한다(§4).

**암호구 바꾸기**: 새 salt로 새 passKey를 만든다. 그 키로 `pass`를 다시 감싸고 `backupKeyRaw`를 바꾼다. 동기화를 켰다면 드라이브 `watson-key.json`도 새로 올린다(§6.6). 이전 백업 파일은 이전 암호구로만 열린다(지금처럼 안내).

**암호구를 정하지 않은 사람**: DPAPI 사본만 있다. 화면 위에 '백업 암호구를 정해야 PC를 바꾸거나 윈도우 계정이 바뀌어도 자료를 열 수 있습니다'를 늘 보인다(닫기 없음). 백업·동기화는 암호구가 있어야 켜진다(지금과 같음).

## 4. 옮기기(0.x → 1.0, 첫 실행)

**원칙**: 옛 DB(`class-manager`, 평문)는 새 DB가 다 만들어지고 확인될 때까지 손대지 않는다. 새 DB 이름은 `watson-1`이다. 그래서 중간에 꺼져도 옛 DB는 멀쩡하고, 옛 화면(0.18)이 새 DB를 잘못 읽을 일도 없다.

**마법사 단계**
1. 안내: '학생 자료를 이 PC의 윈도우 계정으로 잠급니다. 약 1분.'
2. **안전 백업**: 백업 폴더와 기존 캐시 열쇠가 있으면 옛 DB로 백업 파일을 하나 만든다. 없으면 '백업 파일 내려받기'를 권한다(건너뛸 수 있음, 경고).
3. **암호구 확인**: 백업 암호구가 있으면 한 번 입력받는다. 저장된 확인값(`makeKeyCheck`)으로 맞는지 본다. 틀리면 다시 묻는다.
   - '암호구를 잊었어요' → 새 암호구 정하기. 이전 백업 파일은 이전 암호구로만 열린다는 확인을 받는다.
   - '나중에' → 백업이 꺼진 채로 진행한다(띠로 계속 알림).
   - 암호구가 원래 없으면 이 단계를 건너뛴다.
4. DEK 생성, vault.json 쓰기(dpapi, 암호구가 있으면 pass).
5. 표마다 옛 DB를 읽어 새 DB(미들웨어)에 쓴다. 쓸 때 `updated_at`은 바꾸지 않는다(§5.4 병합 쓰기 표시).
   - `device_local`에서 `backupKey`는 버리고 `backupKeyRaw`를 넣는다.
   - 웹 전용 핸들(백업 폴더 handle)은 버린다. exe에서는 쓰지 않는다.
6. **확인**: 표마다 행 수와 무작위 표본 20행의 내용이 옛 DB와 같은지 본다. 원시 IndexedDB(미들웨어 없이)로 새 DB를 읽어 이름·글이 평문으로 없는지 본다.
7. 새 DB에 `meta.migratedFrom = 'class-manager'` 표시. 그다음 옛 DB를 지운다.
8. 실패하면(3~6 어디서든) 새 DB와 vault.json을 지운다. 옛 DB는 그대로 두고 '다시 시도'·'백업 파일 내려받기'를 보인다. 앱은 열지 않는다(평문과 암호화 두 길을 함께 두지 않음).

**되돌리기 안전**: 업데이트 되돌리기(§8.1)는 1.0 이상 판으로만 돌아간다. 1.0 묶음을 설치하면 1.0 미만 묶음은 지운다. 그래서 1.0 이후 0.x 화면이 열릴 일이 없다.

## 5. 암호화 미들웨어

### 5.1 무엇을 평문으로 두나
행마다 **색인 칸과 동기화용 칸만 평문**이고 나머지는 `_enc` 한 칸으로 암호화한다.

| 표 | 평문 칸 |
| --- | --- |
| 모든 표 | `id`, `updated_at`, `deleted`, `created_at` |
| classes | `school_year`, `grade`, `class_no` |
| students | `class_id` |
| attendance | `student_id`, `date`, `kind` |
| absence_reports | `student_id`, `start_date` |
| report_attendance | `report_id`, `attendance_id` |
| counseling_logs, reflections | `student_id`, `date` |
| seating_charts, cleaning_charts | `class_id` |
| school_calendar, local_events, google_events | `date` |
| teacher_timetable | `weekday`, `period` |
| ai_prompts | `kind` |
| notices | `target_date` |
| briefings | `target_date`, `slot` |
| hwpx_templates | `name`(양식 파일 이름) |
| notice_items | `start_date`, `end_date` |
| note_files | `note_id` |
| todos | `order` |
| chat_log | `at`, `school_year` |

- 이 목록은 스키마 색인에서 **자동으로 뽑는다**(`db.tables[].schema.indexes`). 손으로 적지 않는다. 그래야 색인을 더하면 자동으로 평문 목록에 들어간다. 이름·글이 색인이 되지 않게 하는 시험을 둔다.
- 평문으로 남는 것이 드러내는 것: 학생 id별 출결 날짜·종류(결석/지각 등), 상담·반성문 날짜, 학급 번호. 이름·사유·내용·연락처는 드러나지 않는다(받아들임).
- 암호화하지 않는 표: `neis_cache`(학교 공개 자료).
- `device_local`도 암호화한다. 키 이름(id)만 평문이다.

### 5.2 암호문 형식(v1, 플랫폼 중립)
`_enc` = base64( `0x01`(판) ‖ iv(12) ‖ AES-256-GCM(DEK, plaintext, aad) )
- aad = UTF-8(`watson-row:v1:` + 표 이름 + `:` + id). 다른 표·다른 행으로 옮겨 붙인 암호문은 풀리지 않는다.
- plaintext = UTF-8(JSON). 직렬화는 `Uint8Array`를 `{"$u8":"base64"}`로 바꾼다(hwpx 양식 원본). 다른 비-JSON 값(CryptoKey·Blob·핸들)은 저장 전에 오류로 막는다(§4에서 없앰).
- 암호: **@noble/ciphers의 동기식 `gcm`**(MIT, 2.4.0, 2026-08 배포).
  - 이유: Dexie는 묶음 저장(트랜잭션) 안에서 Dexie 밖의 비동기 API를 부르면 묶음이 일찍 끝나 `PrematureCommitError`가 난다(§10). 그래서 WebCrypto는 쓸 수 없다.
  - iv는 `crypto.getRandomValues`로 만든다(동기).

### 5.3 Dexie DBCore 미들웨어
- **쓰기(mutate add/put)**: 평문 칸을 남기고 나머지를 `_enc`로 바꾼다. **이미 `_enc`가 있는 값은 다시 암호화하지 않는다**(동기화 원본 그대로 넣기에 대비).
- **읽기(get/getMany/query values/openCursor)**: `_enc`를 풀어 평문 칸과 합친다. 커서는 감싸서 `value`를 바꾼다. `_enc`가 없는 행(옮기기 중)은 그대로 둔다.
- **delete/deleteRange·keys만 읽기·count**: 그대로 통과.
- 풀기 실패(다른 열쇠·손상)는 **조용히 넘기지 않는다**: 오류 이벤트 + 그 행을 `{id, _broken: true}`로 돌려준다. 화면은 '손상된 기록 n개' 띠를 보인다. 덮어쓰지 않는다.
- 성능 목표: 1만 행 읽기 1초 안, 첨부 150MB 전체 읽기 15초 안(백업·정리 때만 해당). 시험으로 잰다.

### 5.4 `updated_at` 도장(동기화의 바탕)
동기화는 '늦게 고친 쪽이 이긴다'이다. 그래서 모든 쓰기가 `updated_at`을 올려야 한다.
- 미들웨어가 put/add마다 `updated_at = max(지금, 기존 행 updated_at + 1ms)`를 찍는다. 기존 행은 같은 묶음 안에서 `getMany`로 읽는다. 다른 PC 시계가 앞서 있어도 이 PC에서 고친 것이 이긴다.
- 예외는 **병합 쓰기**뿐이다(옮기기·백업 복원·동기화 합치기). 묶음에 `mergeWrite` 표를 달면 도장을 찍지 않는다.
- 미래 시각 막기: 받은 행의 `updated_at`이 지금보다 하루 넘게 앞서면 그 기기 시계가 틀렸다는 경고를 보인다(받기는 함).

## 6. 드라이브 동기화(1.0.x)

### 6.1 무엇을 동기화하나
`SYNC_TABLES` = 백업 표에서 다음을 뺀 것:
- `neis_cache`: 학교 공개 자료, 각 PC가 받는다.
- `school_calendar`: 나이스에서 각 PC가 받는다. 주마다 id가 새로 생겨 오가면 쓸모없이 바뀌기만 한다(코드 리뷰 M2).
- `google_events`: 각 PC가 구글에서 받는다.
- `device_local`: 기기 상태(백업 열쇠, PIN, 지금 학급, 키).

AI 키·나이스 키·PIN은 `device_local`이라 오가지 않는다. 각 PC에서 넣는다.

### 6.2 드라이브 'Watson' 폴더
```
Watson/                         (appProperties.watson = "root")
  watson-key.json               {v, keyId, salt, iter, iv, ct, check, updatedAt}  ← vault의 pass와 같은 형식
  devices/<deviceId>.wsync      그 기기의 스냅숏(암호문)
  files/<fileId>.wfile          첨부 내용(암호문, 한 번만 올림)
```
- **폴더 찾기**: `drive.file`이라 이 앱이 만든 것만 보인다. `appProperties` 표로 찾는다. 폴더 id는 기기에 기억한다.
  - 둘 이상이면 가장 먼저 만든 것을 쓴다.
  - 휴지통·삭제된 폴더면 '드라이브 폴더가 없어졌습니다: 다시 만들까요?'.
- **`.wsync` 형식**: `0x01` ‖ iv ‖ AES-GCM(DEK, gzip(JSON{v:1, deviceId, deviceName, at, keyId, tables:{표:[평문 행…]}}), aad='watson-sync:v1:'+deviceId). 첨부 내용은 빼고 첨부 행 메타만 넣는다.
- **`.wfile` 형식**: `0x01` ‖ iv ‖ AES-GCM(DEK, 원본 바이트, aad='watson-file:v1:'+fileId).
- 각 기기는 **자기 `.wsync`만 덮어쓴다**. 공유 파일(`watson-key.json`)은 드물게만 쓴다. 그래서 쓰기 충돌이 거의 없다.

### 6.3 켜기(설정 > 구글 계정 > 이 PC 동기화 켜기)
조건: 구글로 시작함, 백업 암호구 있음, 1.0 암호화 완료.
1. 드라이브에 `watson-key.json`이 **없으면**(첫 PC): 폴더와 열쇠 파일을 만들고 내 스냅숏을 올린다.
2. **있으면**(두 번째 PC부터): 드라이브 암호구를 묻는다. 열쇠 파일을 풀어 드라이브 DEK를 얻는다.
   - `keyId`가 이 PC와 다르면 이 PC 자료를 드라이브 DEK로 **다시 암호화**한다(§4와 같은 새 DB 복사 방식, 새 이름 `watson-1b`). vault를 바꾼다.
   - 이 PC의 백업 암호구는 드라이브 암호구로 바뀐다. 이전 백업은 이전 암호구로 연다는 확인을 받는다.
3. **처음 합치기 선택**: 양쪽 자료 개수(학급·학생·기록·노트)를 보여 주고 고르게 한다.
   - **드라이브 자료로 바꾸기**(이 PC에 자료가 거의 없을 때 권장): 안전 백업 → 이 PC 표를 비우고 드라이브 자료로 채운다.
   - **합치기**: §6.4 규칙대로 합친다. 같은 학년도·학년·반 학급이 둘이면 하나로 묶을지 묻는다(학생은 번호+이름이 같으면 같은 학생으로 본다). 그 밖의 겹침은 §6.5가 정리한다.

### 6.4 동기화 한 번(sync cycle)
언제 도나: 앱을 켤 때, 쓰기 뒤 60초 조용하면, 10분마다, 창이 다시 보일 때, 닫기 직전(최대 3초, §8.7). 한 번에 하나만 돈다.
1. `files.list`로 `devices/` 파일과 `modifiedTime`을 가져온다. 마지막으로 본 시각보다 새것만 내려받는다.
2. 각 파일을 풀고(`keyId`가 다르거나 풀 수 없으면 그 기기는 건너뛰고 알림) 합친다. 합치기는 **한 번의 병합 쓰기 묶음**이다. 표마다 같은 id 행은 `updated_at`이 늦은 쪽이 이긴다. 같으면 내용 해시가 큰 쪽이 이긴다(모든 기기가 같은 결론을 내도록).
   - **지움**: 지운 표시(`deleted`)도 행이라 그대로 전해진다. 하드 삭제는 전해지지 않는다. 출결 묘비를 다시 쓰려고 지우는 경우는 아래 겹침 정리로 맞춰진다.
   - **충돌 사본(노트·누가기록)**: 양쪽이 그 기기와의 마지막 동기화 뒤에 고쳤고 내용이 다르면, 진 쪽을 지우지 않고 새 행으로 남긴다. 노트는 제목 앞 '(충돌 사본)', 누가기록은 같은 학생·날짜의 '(충돌 사본)' 기록. 홈 띠로 알린다.
3. 합친 뒤 §6.5 겹침 정리를 하고, 영향받은 학생의 결석신고서를 다시 맞춘다(`reconcileStudent`, 제출·고친 신고서는 지금처럼 보존).
4. 받은 첨부 행 중 이 PC에 내용이 없는 것은 `files/`에서 내려받는다.
5. 이 기기에 마지막 올리기 뒤 바뀐 것이 있으면 새 첨부를 `files/`에 올리고 내 `.wsync`를 덮어쓴다. 바뀐 것은 미들웨어가 쓰기마다 올리는 `changeSeq`로 안다.
6. 상태를 저장한다: 기기별로 마지막으로 본 `modifiedTime`, 마지막 성공 시각, 마지막 오류.
- 합치기 전 **안전 백업**: 백업 폴더가 있으면 하루 한 번 동기화 직전 백업을 만든다(자동 백업과 같은 줄에서 돈다).

### 6.5 겹침 정리(논리적 고유 키)
서로 다른 PC가 같은 것을 따로 만들면 id가 달라 둘 다 남는다. 합친 뒤 아래 규칙으로 정리한다. 고르는 기준은 모든 기기가 같은 결론에 이르는 결정적 규칙(updated_at, 같으면 id)이다.

| 대상 | 같은 것으로 보는 기준 | 정리 |
| --- | --- | --- |
| 출결(고유 색인) | student_id+date+kind | 늦은 쪽을 남기고 나머지는 이 PC에서 하드 삭제(고유 색인 때문). 병합 묶음 안에서 먼저 정리한 뒤 넣는다 |
| 지시문 ai_prompts | kind의 active | 가장 늦은 것만 active |
| 반성문 좋은 글 기본값 | 기본 글 묶음(PC마다 처음 한 번 넣음) | 같은 글은 하나만 |
| 내 시간표 | weekday+period+source | 늦은 것 하나 |
| 전달사항 짝 노트 | notice_date | 늦게 고친 것이 짝. 다른 노트는 짝을 풀고 남김(내용 잃지 않음) |
| 결석신고서 연결 | report_id+attendance_id | 하나만 |
| 학급 | school_year+grade+class_no | 자동으로 합치지 않는다(처음 합치기 때 묻기, §6.3) |
| 설정 app_settings | 한 행 | 늦게 고친 쪽(필드 병합은 범위 밖) |

### 6.6 열쇠·암호구가 다른 PC에서 바뀌면
- 동기화 때 `watson-key.json`의 `updatedAt`이 바뀐 것을 보면 이 PC의 백업 열쇠가 낡은 것이다. '다른 PC에서 백업 암호구를 바꿨습니다. 새 암호구를 입력하세요'를 띠로 보이고, 입력하면 `pass`와 `backupKeyRaw`를 새로 맞춘다. DEK는 같아서 동기화는 계속 된다.
- 연결 끊기: 이 기기의 `.wsync`를 지우고 동기화 상태를 비운다. 자료는 이 PC에 남는다.
- 잃어버린 PC: 다른 PC에서 '기기 목록 > 이 기기 빼기'는 그 `.wsync`만 지운다. 구글 계정 보안의 '타사 액세스' 해제를 안내한다(도둑 PC의 구글 연결을 끊는 유일한 방법).

### 6.7 화면
- 설정 > 구글 계정: 연결 계정, 동기화 켬/끔, 마지막 동기화(상대 시각), 기기 목록(이름·마지막 시각·이 PC 표시), '지금 동기화', '이 기기 연결 끊기', 최근 오류.
- 사이드바 아래 작은 상태: 동기화됨 / 동기화 중 / 오류(누르면 설정). 실패를 조용히 넘기지 않는다.
- 충돌 사본·시계 경고·손상 행은 홈 띠로 알린다.

## 7. 구글로 시작

- 설정 탭 '구글 캘린더' → '구글 계정'으로 바꾼다.
- **구글로 시작**: 권한 `openid email profile https://www.googleapis.com/auth/drive.file`. 모두 비민감이다(드라이브 권한 표, §10). 로그인 뒤 `userinfo`로 이메일을 받아 보여 준다.
- **캘린더도 연결**: 지금의 캘린더 세 권한을 `include_granted_scopes=true`로 더한다(점진 동의).
  - 받은 권한 목록을 저장하고, 화면은 받은 권한에 맞춰 기능을 켠다.
  - 이미 캘린더로 로그인한 사람은 그대로 쓰고, 동기화를 켤 때 드라이브 권한만 더 받는다.
- **토큰**: 메인만 가진다. safeStorage 비동기로 감싼다. 쓸 수 없으면 저장하지 않고 매번 로그인(평문 저장 제거, 보안 점검 L7).
- **API 통로**(메인 `google:api`): 주소를 `new URL`로 해석해 정규화한 뒤 허용 목록과 비교한다(`../`·`%2e` 우회 막음, 보안 점검 L1).
  - 허용 주소: `www.googleapis.com/calendar/v3/…`, `/drive/v3/files…`, `/upload/drive/v3/files…`, `/oauth2/v3/userinfo`.
  - 바이너리 본문(업로드)과 바이너리 응답(내려받기)을 지원한다. 크기 상한: 파일 하나 60MB.
- **오류 안내**: `admin_policy_enforced`·`access_not_configured`(학교 구글 계정) → '개인 Gmail을 쓰거나 학교 관리자에게 앱 등록을 부탁하세요'. 토큰 만료·취소 → '다시 연결' 단추.

## 8. exe 보강(메인)

1. **업데이트 서명·되돌리기**
   - `update.json`에 `sig2` = Ed25519(정해진 순서의 JSON `{version, shell, bundle, sha256, note, date, expires}`)를 더한다. 옛 exe용 `sig`는 그대로 둔다. `expires` = 배포일 + 120일. 넘으면 '업데이트 확인이 오래됐습니다' 경고만 한다.
   - 묶음 zip 안에 `manifest.json`(파일별 sha256)을 넣는다. 설치 때 확인하고, 켤 때마다 다시 확인한다. 다르면 이전 판으로 돌아가고 알린다.
   - `current.json` = `{version, dir, prev:{version, dir}, pending}`. 새 판을 설치하면 `pending=true`이다. `app:ready`가 오면 false로 바꾼다. 다음 실행 때 `pending`이 여전히 true면(새 판이 첫 화면을 못 그림) `prev`로 돌아가고 그 판을 '건너뛸 판'에 적는다.
   - 1.0 이상 묶음을 설치하면 1.0 미만 묶음은 지운다(§4 되돌리기 안전).
2. **Electron fuses**: `afterPack` 훅에서 `@electron/fuses`로 runAsNode·NodeOptions·inspect 인자를 끄고 쿠키 암호화를 켠다. file 프로토콜 특권은 끈다(앱은 `app://`만 씀).
   - **asar 무결성 검사는 켜지 않는다**: electron-builder 25는 Windows에 무결성 해시를 넣지 않고, 해시가 없으면 앱이 강제 종료된다(§10). 화면 묶음은 asar 밖(업데이트 폴더)에 있어 §8.1의 manifest가 대신 지킨다.
3. **권한 처리기**: `setPermissionRequestHandler`·`setPermissionCheckHandler`로 `media`(마이크, 음성 받아쓰기)만 허용하고 나머지는 거부한다.
4. **폴더 통로**: 노트 '폴더' 블록은 사용자가 대화상자로 고른 폴더(메인이 목록 기억) 안의 경로만 목록·열기를 허용한다. 받아쓰기 `stt:run`도 대화상자로 고른 파일만 받는다.
5. **외부 프로그램**: `claude`·`agy`는 PATH에서 찾은 **절대 경로**로, 앱 자료 폴더의 `ai-work`에서 실행한다(임시 폴더 심기 막음). Antigravity에는 글을 **표준 입력**으로 넘긴다(명령줄 기록에 상담 내용이 남지 않게, 보안 점검 M2). `agy`가 표준 입력을 받지 못하는 판이면 권한 600 임시 파일 경로로 넘기고 바로 지운다.
6. **CSP**: `form-action 'none'`, `frame-src 'none'`, `object-src 'none'`. `raw.githubusercontent.com`을 뺀다(업데이트는 메인만 받음). 드라이브 주소는 메인만 부르므로 넣지 않는다. AI 주소는 지금 그대로.
7. **닫기 전 저장**: 창 `close`에서 한 번 막고 `app:before-close`를 보낸다. 화면이 `flushAll()`과 동기화 올리기를 하고 `app:close-ok`를 보내면(최대 3초) 닫는다. Windows 로그오프(`query-session-end`)도 같은 길이다.
8. **자동 실행·바로가기**: 실제 exe 경로는 `PORTABLE_EXECUTABLE_FILE` 환경 변수다(포터블은 임시 폴더에서 돈다, §10).
   - '컴퓨터를 켜면 Watson 열기'는 `app.setLoginItemSettings({openAtLogin, path})`.
   - '바탕화면 바로가기 만들기'는 `shell.writeShortcutLink`.
   - 켤 때 exe 경로가 바뀌었으면(옮김) 자동 실행 경로를 고친다.
   - 0.13의 .cmd 도우미와 안내는 지운다.
9. **바뀌지 않는 것**: 창 격리·샌드박스·IPC 발신자 확인·app 프로토콜 경로 검사·업데이트 Ed25519 확인(유지).

## 9. 시험·검증

**자동 시험(Vitest, fake-indexeddb)**
- **미들웨어**
  - 표마다 넣기·바꾸기·지우기·색인 검색·고유 색인·`modify`·커서·liveQuery가 그대로 되는지 본다.
  - 원시 저장값에 이름·글·전화가 없는지 본다(표본 자료로 문자열 검색).
  - 다른 열쇠나 손상된 행은 `_broken`이 되고 덮어쓰지 않는지 본다.
  - `updated_at` 도장(시계가 앞선 행 포함)과 병합 쓰기 예외를 본다.
- **옮기기**: 평문 → 암호화 후 내용이 같은지, 3단계와 5단계 중간 실패 뒤 옛 DB가 그대로인지, 암호구가 틀리거나 잊은 경우와 '나중에'를 고른 경우를 본다.
- **vault**: dpapi 실패 → 암호구로 열기, 잘못된 암호구 5번, vault.json 손상 → .bak, 암호구 바꾸기를 본다.
- **동기화**(메모리 가짜 드라이브)
  - 두 기기와 세 기기로: 만들기·고치기·지우기 전파를 본다.
  - 노트·누가기록 충돌 사본, 출결 고유 키 겹침, 기본 글 겹침, 짝 노트 겹침, 첨부 오가기를 본다.
  - 열쇠가 다른 기기, 암호구가 바뀐 경우, 시계가 하루 앞선 기기, 폴더가 지워진 경우, 네트워크 실패 후 다시 시도를 본다.
  - 같은 자료로 세 번 돌려도 바뀌는 것이 없는지 본다.
- **메인(Node)**: 구글 주소 정규화(우회 시도 목록), `sig2`·manifest·되돌리기 판정, 폴더 통로 범위, 닫기 손잡이 시간 초과.
- **성능**: 1만 행·첨부 150MB에서 읽기와 백업 시간을 잰다.

**빌드 확인(여기서)**: exe를 빌드한 뒤 fuses 값을 `@electron/fuses read`로 확인하고, CSP 헤더를 확인한다.

## 10. 확인한 사실(이 설계의 근거)
- **Dexie**: 묶음 저장 안에서 Dexie 밖 비동기 API를 부르면 묶음이 일찍 끝난다. Dexie는 그런 API를 묶음 밖에서 부르라고 한다(PrematureCommitError 문서). → 동기식 암호를 쓴다.
- **safeStorage**: Windows에서 DPAPI로 열쇠를 만들거나 보호한다. 다른 사용자에게서는 지키지만 **같은 사용자 공간의 다른 앱에서는 지키지 못한다**. 동기 API는 Electron 46에서 제거 예정이고 비동기 API가 권장된다(Electron safeStorage 문서). 설치된 Electron 44.10.2에 `encryptStringAsync`·`isAsyncEncryptionAvailable`이 있다(타입 정의 확인).
- **ASAR 무결성**: Windows는 Electron 30부터 된다. electron-builder는 해시를 직접 넣어야 하고, 해시가 없거나 틀리면 앱이 강제 종료된다(Electron 문서). 설치된 app-builder-lib 25.1.8에는 `electronFuses` 설정이 없다(v27 문서에만 있음). → fuses는 afterPack 훅으로, 무결성 검사는 끈다.
- **`drive.file`**: 앱이 만들거나 사용자가 그 앱으로 연 파일만 볼 수 있다. 비민감 권한이다. 문서에는 '앱'이 OAuth 클라이언트 단위인지 프로젝트 단위인지 적혀 있지 않다. **PC끼리는 같은 데스크톱 클라이언트라 상관없다.** 휴대폰 앱(1.1)은 다른 클라이언트이므로 1.1 설계 전에 작은 시험으로 확인한다. 안 되면 휴대폰에서 구글 파일 선택기로 'Watson' 폴더를 한 번 고르게 한다.
- **포터블 exe**: electron-builder 포터블은 실제 exe 경로를 `PORTABLE_EXECUTABLE_FILE`로 준다.
- **Electron 44 API**: `query-session-end`·`setLoginItemSettings`·`writeShortcutLink`가 있다(타입 정의 확인).
- **코드 조사**
  - 색인 칸에 이름·글이 없다.
  - 하드 삭제는 출결 묘비 재사용, 나이스 학사일정 다시 받기, 구글 일정 다시 받기뿐이다.
  - 저장값 중 비-JSON은 hwpx 양식(`Uint8Array`), 백업 열쇠(CryptoKey), 웹 폴더 핸들이다.
  - `localStorage`에는 화면 배치·모양만 있다(학생 자료 없음).
  - PC마다 처음 한 번 넣는 자료(반성문 기본 글, 지시문)는 동기화 때 겹친다.

## 11. 열린 질문(구현 전에 정함)
1. 동기화 첫 합치기에서 같은 학급을 묶을 때의 학생 짝짓기 기준(번호+이름)을 화면에서 확인받을지, 자동으로 할지. 제안: 확인받기.
2. `chat_log`(대화 기록)도 PC끼리 오가게 할지. 제안: 오가게(학년도 안).
3. 충돌 사본을 홈 띠 말고 노트함 상단에도 모을지. 제안: 노트함 '충돌 사본' 폴더.
