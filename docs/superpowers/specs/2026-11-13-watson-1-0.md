## 0. 목표와 하지 않는 것

**목표**
1. 노트북 도난·디스크 복사로 학생 자료가 읽히지 않는다(옛 평문 흔적은 §4.6).
2. 학교 PC와 집 PC가 같은 자료를 본다. 드라이브에는 암호문만 있다.
3. 구글 연결이 깔끔하다(경고 화면 없이 시작, 캘린더는 따로).
4. exe 쪽 보안 구멍(보안 점검)을 막는다.
5. **무엇이 실패해도 자료를 잃지 않는다.** 열쇠를 여는 길이 늘 둘 이상 있고, 되돌아갈 백업이 있다.

**하지 않는 것(1.0)**: 휴대폰 앱, 한글 문서 작성(rhwp), 코드 서명 인증서, 필드 단위 설정 병합, 실시간(초 단위) 동기화, 교사 간 공유, 학급 자동 합치기.

**위협 모델**: 잠기지 않은 채 켜 둔 PC에서의 열람과 같은 윈도우 계정으로 도는 악성 프로그램은 막지 못한다(DPAPI 한계, §13). 막는 것: 꺼진 노트북 도난, 디스크·폴더 복사, 드라이브 계정 유출(암호문만), 업데이트 통로 변조.

## 2. 시작 순서(exe)

```
React 뿌리 붙음 → bundle:alive (메인, §9.1 되돌리기 판정용)
 └ vault:status
    ├ none        → §4 옮기기 마법사(옛 DB가 있으면) 또는 첫 설치 마법사(암호구 정하기)
    ├ ok          → 메인이 DPAPI로 DEK를 풀어 넘김 → DB 열기 → PIN(있으면) → 앱
    ├ needs-pass  → '자료 열기': 백업 암호구 / 복구 코드 / 드라이브 열쇠 파일+암호구 → DPAPI로 다시 감쌈 → 위와 같음
    └ broken      → vault.json.bak 시도 → 실패하면 '자료 열기'(위 세 길) 또는 '백업 파일에서 복원'
웹(개발·캡처): vault 없음 → 평문 DB 'class-manager'(지금과 같음)
```
- **`AppProviders`(DB를 쓰는 모든 것)는 vault가 풀린 뒤에만 붙는다.** 지금은 `App`의 `useMemo`에서 `createDb()`가 바로 열리고 StartupTasks·구글 자동 동기화·백업 띠가 곧바로 돈다(App.tsx:49). 1.0에서는 `VaultGate` 바깥에는 DB가 없다.
- 단일 실행 잠금은 이미 있다(main.cjs:45). 유지한다.

## 3. 열쇠(vault)

**DEK(자료 열쇠)**: 무작위 32바이트, `keyId`(uuid). 렌더러 메모리에만 평문으로 있다.

**열쇠를 여는 길(최소 둘 이상 필수)**
1. **DPAPI**: safeStorage 비동기 API로 감쌈. 같은 PC·같은 윈도우 계정이면 묻지 않음.
2. **백업 암호구(필수)**: `passKey` = PBKDF2-SHA256(암호구, salt, 600k) → AES-256-GCM. **1.0은 암호구 없이 시작하지 않는다.**
3. **복구 코드(권장)**: 무작위 25자(5자×5묶음, 헷갈리는 글자 뺌, 약 120비트). PBKDF2 10만 회로 감쌈. 처음 한 번 보여 주고 '인쇄/파일로 저장'. 다시 만들면 이전 코드는 무효.

**보관 파일** `%APPDATA%\Watson\vault.json`(임시 파일 쓰기 → fsync → 이름 바꾸기, 직전 판 `.bak`)
```json
{ "v": 1, "keyId": "…", "dbName": "watson-1a2b3c4d",
  "dpapi": "b64(encryptStringAsync(b64 DEK))",
  "pass":  { "salt": "b64", "iter": 600000, "iv": "b64", "ct": "b64", "updatedAt": "…" },
  "recovery": { "salt": "b64", "iter": 100000, "iv": "b64", "ct": "b64" } }
```
- 감쌀 때 aad: `watson-dek:v1:pass:`+keyId / `…:recovery:`+keyId.
- **같은 passKey를 세 곳에 쓴다**: 백업 파일 암호화, DEK 감싸기, 확인값. 매번 iv가 무작위이고 aad가 서로 달라 안전하다(검토 확인). 확인값 aad는 `watson-check:v1`로 따로 둔다(지금은 빈 aad).
- safeStorage는 비동기 API(`encryptStringAsync`/`decryptStringAsync`)를 쓴다. `shouldReEncrypt`면 다시 감싼다.
  - `isAsyncEncryptionAvailable()`이 거짓이면 DPAPI 길 없이 암호구·복구 코드로만 연다. 이 경우 켤 때마다 암호구를 묻는다. 화면에 이유를 보인다.
- **백업 열쇠 캐시 바꾸기**: 지금의 꺼낼 수 없는 CryptoKey(`device_local.backupKey`, 브라우저가 원시 바이트로 디스크에 씀, 보안 H2)를 없앤다. passKey 원시 바이트를 **암호화된** `device_local.backupKeyRaw`에 둔다.
- **암호구 바꾸기**: 새 salt → 새 passKey → `pass`·`backupKeyRaw` 다시 쓰기. 동기화 중이면 드라이브 `watson-key.json`도 바꾼다(§7.7). 이전 백업 파일은 이전 암호구로만 열린다(안내).

## 4. 옮기기(0.x → 1.0) 와 첫 설치

### 4.1 원칙
- 옛 DB(`class-manager`, 평문)는 새 DB가 완성되고 확인되기 전까지 손대지 않는다. 새 DB 이름은 `watson-<keyId 앞 8자>`이다(다시 암호화할 때도 같은 규칙).
- **옛 DB를 지우는 조건**:
  1. vault.json에 DPAPI 말고 다른 길(암호구)이 기록돼 있다.
  2. 새 DB 검증을 통과했다.
  3. 새 DB로 만든 백업 파일 하나를 백업 폴더에 썼거나, 선생님이 '내려받기'로 받았다.

  셋 중 하나라도 아니면 옛 DB를 남기고 앱도 열지 않는다(평문·암호화 두 길을 함께 두지 않음).
- **디스크 공간**: 시작 전에 `navigator.storage.estimate()`로 남은 할당량을 본다. 현재 사용량 × 1.3이 남아야 한다(두 벌이 잠시 함께 있음). 모자라면 이유를 알리고 멈춘다.

### 4.2 마법사 단계
1. 안내('학생 자료를 이 PC의 윈도우 계정과 백업 암호구로 잠급니다. 약 1분. 끝까지 창을 닫지 마세요').
2. **옛 DB 백업**: 백업 폴더와 옛 캐시 열쇠가 있으면 지금 형식으로 백업 하나. 없으면 다음 단계 뒤에 새 DB로 만든다(4.1 조건 3).
3. **암호구**: 있으면 입력받아 확인값으로 맞는지 본다. 없으면 지금 정한다(8자 이상).
   - '잊었어요' → 새로 정하기(이전 백업 파일은 이전 암호구로만 열린다는 확인).
   - **'나중에'는 없다.**
4. **복구 코드**: 만들어 보여 준다. '인쇄', '파일로 저장', '건너뛰기(권장하지 않음)'.
5. DEK 생성, vault.json 쓰기.
6. 표마다 옛 DB → 새 DB 복사(병합 쓰기, 원래 `updated_at` 유지). 1천 행씩 묶음으로, 진행 막대를 보인다.
   - `device_local`: `backupKey` 대신 `backupKeyRaw`. 웹 폴더 핸들은 버린다.
   - `note_files`: 내용(base64)을 바이트로 풀어 `note_blobs`로 나눠 넣는다(§5.6).
   - 파생 행(결석신고서·추정 시간표·기본 글)의 id를 결정적 id로 바꾼다(§7.3). 결석신고서는 다른 표(`report_attendance`, 학생 화면)가 id로 가리키므로 함께 바꾼다.
7. **확인**: 표마다 행 수, 무작위 표본 20행의 내용 동일, 원시 IndexedDB(미들웨어 없이)에서 표본 이름·글·전화 문자열이 보이지 않음.
8. 새 DB로 백업 1개(4.1 조건 3).
9. 옛 DB 연결을 닫고 `Dexie.delete('class-manager')`. 새 DB에 `meta.migratedFrom`을 남긴다.
10. **한 번만 안내**: '이전 평문 자료의 흔적이 디스크에 남아 있을 수 있습니다. 윈도우의 BitLocker(장치 암호화)를 켜 두세요.'(§4.6)

**실패**(어느 단계든): 새 DB·vault.json을 지운다. 옛 DB는 그대로다. '다시 시도', '백업 파일 내려받기'를 보인다.
**도중에 꺼짐**: 다음 실행 때 vault.json은 있는데 새 DB에 `meta.complete`가 없으면 새 DB·vault를 지우고 처음부터 한다.

### 4.3 첫 설치(옛 DB 없음)
암호구 정하기 → 복구 코드 → DEK → 빈 새 DB. 동기화를 켜려는 두 번째 PC는 '드라이브에서 가져오기'를 고를 수 있다(§7.4).

### 4.4 되돌리기 안전
업데이트 되돌리기(§9.1)는 1.0 이상 판으로만 간다. 1.0 묶음을 설치하면 1.0 미만 묶음은 지운다.

### 4.5 백업 복원(1.0 이후)
- 동기화 꺼짐: 지금처럼(백업에 있는 표만 바꿈, 병합 쓰기).
- **동기화 켜짐**:
  - 복원은 **도장 찍는 보통 쓰기**다. 백업에 없는 행은 `clear()`로 하드 삭제하지 않고 도장 찍은 지움 표시로 바꾼다. 그래야 다음 동기화에서 다른 PC에 '복원'이 퍼지고, 옛 자료가 되살아나지 않는다(검토 M1).
  - 화면에 '모든 PC에 이 백업 내용으로 되돌립니다'를 확인받는다.
  - 복원하는 동안 동기화를 멈추고, 끝나면 바로 올린다.

### 4.6 정직한 한계
옛 DB를 지워도 브라우저 저장 파일(LevelDB)의 지난 조각이 디스크에 남을 수 있다. 1.0은 이를 지우지 못한다. 그래서 BitLocker를 안내한다(한 번).

### 4.7 옛 exe 지킴이(0.18.1)
포터블 exe는 바탕화면·USB에 남는다. SHELL ≤6 exe가 1.0 이후에 켜지면, 옛 화면은 `class-manager`가 없으니 빈 평문 DB를 만든다. 그 상태로 자동 백업을 같은 폴더에 쓰면 14일 정리에서 진짜 백업을 밀어낸다(검토 M2).
- 0.18.1(옛 exe용 마지막 렌더러)은 켤 때 `indexedDB.databases()`에 `watson-`으로 시작하는 DB가 있는지 본다. 있으면 '이 exe는 오래됐습니다. 새 Watson.exe를 쓰세요'만 띄우고 DB를 열지 않는다.
- 1.0의 자동 백업 정리는 이 기기가 만든 파일만 센다(파일 이름에 기기 표시를 넣는다).

## 5. 암호화 미들웨어

### 5.1 새 DB 스키마(watson-*)
새 DB라 스키마를 다듬는다. 바꾸는 것만 적는다.
- `hwpx_templates.name` 색인 뺌: 올린 파일 이름이라 학생 이름이 들어갈 수 있다(template.ts:70). 쓰는 곳 없음.
- `notes.updated_at` 색인 뺌: JS에서 정렬한다.
- `note_files` = 메타만(id, note_id, name, mime, size, created_at…). 내용은 `note_blobs`(id → 암호 바이트)로 나눈다(§5.6).
- `meta` 표(기기 전용, 동기화·백업 안 함): migratedFrom, complete, schema 판.
- `sync_rows` 표(기기 전용): 행마다 `base_hash`(§7.2).

### 5.2 무엇을 평문으로 두나
- 평문 칸 = 스키마 색인 칸(복합 색인의 각 칸 포함, **자동 추출**) + `id`, `updated_at`, `deleted`.
  - `created_at`은 평문이 아니다.
  - 시험이 '이름·글·연락처 칸은 색인이 아니다'를 지킨다.
- 표별로 드러나는 것: 학생 id별 출결 날짜·종류(`attendance.kind`는 고유 색인 때문에 평문), 상담·반성문 날짜, 학급 학년도·학년·반, 학교 공개 자료(`neis_cache`, 학교를 알 수 있음).
- 이름·사유·내용·연락처·메모는 드러나지 않는다.
- 암호화하지 않는 표: `neis_cache`, `meta`, `sync_rows`(해시뿐).
- `device_local`은 키 이름만 평문이다.

### 5.3 암호문 형식(v1, 플랫폼 중립)
`_enc` = **바이트(Uint8Array)**: `0x01` ‖ iv(12) ‖ AES-256-GCM(DEK, plaintext, aad)
- base64로 감싸지 않는다(검토 M7: 크기·시간 두 배).
- plaintext = UTF-8(정규 JSON(행 전체 — 평문 칸도 포함)).
  - **정규 JSON**: 키를 사전순으로, `Uint8Array`는 `{"$u8":"base64"}`, `undefined` 칸은 뺀다.
  - 풀었을 때 **암호문 안의 값이 정답**이다. 평문 칸이 다르면 변조로 보고 `_broken`.
- aad = UTF-8(`watson-row:v1:` + 표 + `:` + id). 다른 표·행으로 옮긴 암호문은 풀리지 않는다.
- 암호: @noble/ciphers 동기식 `gcm`(MIT). iv는 `crypto.getRandomValues`.
  - 실측: 약 43MB/s, 작은 행 1만 개 0.5초(검토).
  - 비동기 WebCrypto는 묶음 저장을 일찍 끝나게 해서(PrematureCommitError) 쓸 수 없다(§13, 검토 실측).

### 5.4 미들웨어 동작(Dexie DBCore)
- **등록**: 단계 ≥3(Hooks 2·관찰 0·캐시 −1보다 위, 검토 확인). `Table.hook`은 쓰지 않는다(지금도 없음, 시험이 막음).
- **쓰기(add/put)**
  - 받은 객체를 바꾸지 않고 복사본을 만든다(Dexie가 키를 되써 넣음).
  - 평문 칸만 남기고 `_enc`를 만든다.
  - `_broken` 표시가 있는 값은 **거부**한다.
  - `_enc`가 들어 있는 값은 `rawWrite` 표가 붙은 묶음에서만 그대로 넣는다(동기화·옮기기). 그 밖에서는 오류.
  - `changeSpec`/`updates`/`criteria` 같은 요청 부속은 평문 칸만 남기거나 뺀다.
- **읽기(get/getMany/query values/openCursor)**: 풀어서 평문 객체를 돌려준다. `_enc`는 언제나 떼어 낸다. 커서는 `value`를 바꾼 감싸개.
- **풀기 실패**(열쇠 다름·손상·변조)
  - 보통 읽기에서는 그 행을 **빼고** 알린다(오류 이벤트, '손상된 기록 n개' 띠).
  - `repair` 읽기 API로만 원시 행을 볼 수 있다.
  - 내보내기·동기화·`modify`는 손상 행을 건너뛴다. 원래 `_enc`는 그대로 남는다(덮어쓰지 않음).
- delete/deleteRange·키만 읽기·count는 그대로 통과.

### 5.5 `updated_at` 도장
- put/add마다 `updated_at = max(지금, 기존 행 updated_at + 1ms)`. 기존 행은 같은 묶음 안에서 `getMany`로 읽는다(검토 실측: bulkPut·modify·update·anyOf·고유 색인 위반·filter·liveQuery 모두 정상).
- 쓰기 응답으로 실제 찍힌 값을 돌려준다. `save()` 같은 도우미는 그 값을 쓴다(RosterTab이 updated_at을 key로 씀).
- 예외는 **병합 쓰기** 표(`mergeWrite`)가 붙은 **명시적 묶음**(`db.transaction`의 idbtrans 표)뿐이다(옮기기·동기화 합치기·동기화 꺼진 복원). 자동 묶음은 병합이 될 수 없다.
- 받은 행이 지금보다 하루 넘게 앞서면 '○○ PC 시계가 틀렸습니다' 경고(받기는 함).

### 5.6 첨부(note_blobs)
- `note_blobs`: `{id, _enc: 바이트}`. 원본 바이트를 암호화한 것이다(base64 없음). aad = `watson-blob:v1:`+id.
- 크기 합·정리(`cleanupOrphanFiles`)·목록은 메타 표만 읽는다. 내용은 `readFile`할 때만 푼다.
- 큰 파일(>8MB)은 1MB 조각으로 나눠 암호화한다. 화면을 멈추지 않게 조각 사이에 양보한다(묶음 밖에서 암호화한 뒤 짧은 묶음으로 넣음).
- 백업 스냅숏 형식은 `note_files.data`(base64)를 그대로 쓴다. 내보낼 때 blob을 base64로 바꾸고, 들여올 때 되돌린다(백업 형식 2 유지).

## 6. 구글로 시작

- 설정 탭 '구글 캘린더'를 '구글 계정'으로 바꾼다.
- **구글로 시작**: 권한 `openid email profile https://www.googleapis.com/auth/drive.file`. 모두 비민감이다(§13).
  - 이메일은 토큰 응답의 `id_token`에서 읽는다(따로 userinfo를 부르지 않음). 토큰 응답의 `scope`(받은 권한)를 저장한다.
- **캘린더도 연결**: 지금의 캘린더 세 권한을 `include_granted_scopes=true`로 더한다. 설치형(루프백+PKCE)에서도 된다(검토 확인).
  - 캘린더 권한은 '민감'이다. 검수 전에는 경고 화면이 뜨고 100명 제한에 든다. 화면에 '캘린더 연결 때 구글 경고가 나올 수 있습니다'를 미리 말한다.
- `prompt=consent`는 처음 연결 때만. 이미 캘린더로 로그인한 사람은 동기화를 켤 때 드라이브 권한만 더 받는다.
- **토큰**: 메인만 가진다. safeStorage 비동기로 감싼다. 쓸 수 없으면 저장하지 않는다(평문 저장 제거, 보안 L7).
- **API 통로**(메인 `google:api`)
  - `new URL`로 해석해 정규화한 뒤 허용 목록과 맞춘다(우회 막음, 보안 L1). 허용: `www.googleapis.com/calendar/v3/`, `/drive/v3/files`, `/upload/drive/v3/files`.
  - **바이너리 본문·응답, 응답 머리글**(Location 등) 지원.
  - **이어 올리기(resumable) 업로드**를 메인이 직접 한다(5MB 넘는 파일, 검토 M8). 실패하면 이어서 다시 시도.
  - 파일 하나 상한 60MB.
- **오류 안내**
  - `admin_policy_enforced`·`access_not_configured` → 개인 Gmail 또는 학교 관리자 안내.
  - 401(만료·취소) → '다시 연결'.
  - 403 할당량 → 잠시 뒤 다시.
  - 드라이브 저장 공간 가득 → 안내.

## 7. 드라이브 동기화(1.0.x)

### 7.1 무엇을 동기화하나
`SYNC_TABLES` = 백업 표에서 다음을 뺀 것.
- `neis_cache`·`school_calendar`·`google_events`: 각 PC가 원본에서 받는다.
- `device_local`·`meta`·`sync_rows`: 기기 전용.
- `teacher_timetable`의 **추정 행**(`source:'estimated'`): 각 PC가 나이스에서 다시 만든다(검토 B3). 손으로 넣은 행은 동기화한다.

`chat_log`는 동기화한다(학년도 안). AI 키·나이스 키·PIN은 `device_local`이라 오가지 않는다.

### 7.2 동기화 메타데이터
- **기기 id**: 처음 켤 때 만드는 무작위 id(`device_local.deviceId`). 기기 이름(컴퓨터 이름, 바꿀 수 있음).
- **행 해시** = SHA-256(정규 JSON(행)). 동기화 메타에 쓰는 해시는 미들웨어 밖에서 계산한다(평문 행).
- **`base_hash`**(행마다, `sync_rows`): 마지막으로 드라이브와 맞춘 그 행의 해시.
  - 충돌 = 로컬 해시 ≠ base, 받은 해시 ≠ base, 로컬 ≠ 받은 것.
  - 한쪽만 바뀌었으면 그쪽을 쓴다.
- **보낼 것이 있나(dirty)**: `SYNC_TABLES` 전체의 `max(updated_at)` > `lastUploadedMax`.
  - 미들웨어가 쓰기마다 카운터를 따로 쓰지 않는다. 다른 표 묶음 안에서 쓸 수 없기 때문이다(검토 B2).
  - 화면 중에는 Dexie `storagemutated` 이벤트로 '바뀜'을 기억한다.
- **합치기는 이긴 값이 로컬과 다른 행만 쓴다.** 그래야 서로 끝없이 올리지 않는다.

### 7.3 파생 자료와 기본값(결정적 id)
서로 다른 PC가 같은 것을 따로 만들 때 id가 같아야 겹치지 않는다(검토 B3).

| 자료 | 결정적 id | 비고 |
| --- | --- | --- |
| 결석신고서 | `report:<student_id>:<start_date>:<kind>:<category>` | `reconcileStudent`가 만들 때 이 id를 씀(1.0.0부터). 옮길 때 기존 것도 바꿈 |
| 신고서–출결 연결 | `ra:<report_id>:<attendance_id>` | |
| 추정 시간표 | 동기화 안 함(§7.1) | |
| 반성문 기본 글 | `phrase-default-<n>`(지금처럼) + **`updated_at = 1970-01-01`의 병합 쓰기** | 어떤 실제 고침·지움 표시도 기본값을 이긴다. 지운 기본 글이 다시 살아나지 않음 |
| 지시문 ai_prompts | 판마다 무작위 id 유지 | kind별로 가장 늦은 active 하나만(§7.6) |
| 전달사항 짝 노트 | 무작위 id 유지 | §7.6 |
| 충돌 사본 | `conflict:<원래 id>:<진 쪽 해시 앞 12자>` | 두 PC가 같은 충돌을 발견해도 사본은 하나 |

### 7.4 드라이브 'Watson' 폴더와 형식
```
Watson/                         (appProperties.watson = "root")
  watson-key.json               {v:1, keyId, salt, iter, iv, ct, check, updatedAt}  (vault.pass와 같은 형식)
  devices/<deviceId>.wsync      그 기기의 스냅숏
  files/<blobId>.wfile          첨부(한 번만 올림)
```
- `.wsync` = `0x01` ‖ iv ‖ AES-GCM(DEK, gzip(정규 JSON{fmt:1, app:'1.0.x', deviceId, deviceName, at, keyId, maxUpdated, tables:{표:[행]}}), aad='watson-sync:v1:'+deviceId).
  - **모르는 표·칸은 버리지 않고 그대로 보관하고 다시 낸다.** PC마다 판이 섞여 돌기 때문이다.
  - `fmt`가 더 큰 파일은 합치지 않고 '이 PC의 Watson을 업데이트하세요'.
- `.wfile` = `0x01` ‖ iv ‖ AES-GCM(DEK, 원본, aad='watson-file:v1:'+blobId).
- **폴더 찾기**: `drive.file`은 이 앱이 만든 것만 보인다. `appProperties`로 찾는다. 둘 이상이면 가장 먼저 만든 것을 쓴다.
- **첫 PC 경쟁**: 폴더·열쇠 파일을 만든 뒤 다시 목록을 본다. 더 오래된 루트가 있으면 내 것을 지우고 '두 번째 PC' 길로 간다.
  - `devices/`가 비어 있지 않은데 `watson-key.json`만 없으면 첫 PC로 보지 않는다. '열쇠 파일이 없어졌습니다: 이 PC 열쇠로 다시 만들까요?'를 묻는다.

### 7.5 켜기
조건: 구글로 시작함, 1.0 암호화 완료.
1. **첫 PC**: 폴더·열쇠 파일·내 스냅숏을 올린다.
2. **두 번째 PC부터**: 드라이브 암호구를 받아 열쇠 파일을 푼다.
   - `keyId`가 다르면 이 PC 자료를 드라이브 DEK로 다시 암호화한다(§4의 새 DB 복사, 새 이름 `watson-<새 keyId 8자>`). vault를 바꾼다.
   - 이 PC 백업 암호구는 드라이브 것으로 바뀐다(이전 백업 안내).
3. **처음 합치기**: 양쪽 개수(학급·학생·기록·노트)를 보여 주고 고르게 한다.
   - **드라이브 자료로 바꾸기**(이 PC 자료가 적으면 권장): 안전 백업 → 비우고 채움.
   - **합치기**: 행 단위로 합친다. **같은 학년도·학년·반 학급이 둘이면 둘 다 남긴다**(자동 합치기는 학생 id를 가리키는 곳이 많아 1.0 범위 밖, 검토 M10). '학급이 둘 생겼습니다: 하나를 지우세요'로 안내한다.

### 7.6 동기화 한 번
언제: 켤 때, 쓰기 뒤 60초 조용하면, 10분마다, 창이 다시 보일 때, 닫기 직전(로컬 저장 뒤, 남은 시간 안에서 최선). 한 번에 하나만 돈다. 자동 백업과 같은 줄을 쓴다.
1. `devices/` 목록과 `modifiedTime`을 받는다. 마지막으로 본 뒤 바뀐 것만 내려받는다.
2. 풀어서 합친다. **하나의 병합 쓰기 묶음**이다. 행마다:
   - 이기는 순서: **살아 있음 > `updated_at` 늦음 > id 큼**(결정적).
   - `base_hash`로 한쪽만 바뀌었는지 본다(§7.2). 양쪽 다 바뀌었으면:
     - 노트·누가기록은 진 쪽을 충돌 사본으로 남긴다(§7.3 id).
     - 나머지는 이기는 순서대로 정한다.
3. **겹침 정리**(같은 묶음 안, `bulkPut`보다 먼저)

   | 대상 | 기준 | 정리 |
   | --- | --- | --- |
   | 출결(고유 색인 `student_id+date+kind`, 지움 표시 행도 포함) | 같은 키 | 이기는 순서로 하나를 남기고, 나머지는 이 PC에서 하드 삭제한 뒤 넣는다 |
   | 지시문 | kind의 active | 가장 늦은 것 하나만 active |
   | 전달사항 짝 노트 | notice_date | 늦게 고친 노트가 짝. 나머지는 짝만 풀고 남김 |
   | 설정 한 행 | — | 행 단위 이기는 순서 |
   | 학급 | 학년도·학년·반 | 합치지 않음(§7.5) |

4. 합친 학생의 결석신고서를 다시 맞춘다(`reconcileStudent`). 결정적 id라 겹치지 않고, 제출·고친 신고서는 보존한다.
5. 없는 첨부는 `files/`에서 받는다.
6. dirty면 새 첨부를 올리고 내 `.wsync`를 덮어쓴다(이어 올리기). 성공하면 `lastUploadedMax`와 합친 행들의 `base_hash`를 갱신한다.
7. 상태 저장: 기기별 마지막 `modifiedTime`, 마지막 성공·오류, 보이는 기기 목록.

- **합치기 전 안전 백업**: 백업 폴더가 있으면 하루 한 번.
- **지움 표시 정리**(묘비 GC): 지움 표시 행은 **180일 지나고 모든 활성 기기의 `.wsync`에서 지워진 것이 확인되면** 하드 삭제한다. '활성'은 90일 안에 올린 기기다.
  - 90일 넘게 조용한 기기 파일은 '오래된 기기'로 표시하고 합치지 않는다. 다시 켜면 그 기기는 '드라이브 자료로 바꾸기'만 할 수 있다(오래된 스냅숏이 지운 것을 되살리지 않게).
- **하드 삭제 목록**(전해지지 않음, 그래서 위 규칙이 필요):
  - 출결 묘비 재사용(attendance.ts:44): 같은 키라 겹침 정리로 맞춰짐.
  - 나이스·구글 다시 받기: 동기화 안 함.
  - 겹침 정리의 진 쪽: 같은 키라 다른 PC도 같은 결론.

### 7.7 열쇠·암호구가 다른 PC에서 바뀌면
- `watson-key.json`의 `updatedAt`이 바뀌면 띠를 보인다: '다른 PC에서 백업 암호구를 바꿨습니다. 새 암호구를 입력하세요' → `pass`·`backupKeyRaw` 갱신. DEK는 같아서 동기화는 계속된다.
- **연결 끊기**: 이 기기의 `.wsync`를 지우고 동기화 상태를 비운다(자료는 남음).
- **잃어버린 PC**: 다른 PC의 '기기 목록 > 이 기기 빼기'는 그 `.wsync`만 지운다. 구글 계정 보안의 '타사 액세스 해제'를 안내한다.

### 7.8 화면
- 설정 > 구글 계정: 계정, 동기화 켬/끔, 마지막 동기화, 기기 목록(이름·마지막·이 PC·오래됨), 지금 동기화, 이 기기 연결 끊기, 최근 오류, 복구 코드 다시 만들기.
- 사이드바 아래 상태: 동기화됨 / 중 / 오류(누르면 설정).
- 홈 띠: 충돌 사본 n개, 시계 경고, 손상 행, 학급 두 개.
- 노트함: '충돌 사본' 묶음.

## 8. 로그·오류·할당량
- **로그**: id·개수·단계·오류 코드만 쓴다. 행 내용·이름·토큰은 절대 쓰지 않는다. 메인 로그(`%APPDATA%\Watson\logs`)는 7일치만 둔다.
- **충돌 덤프(crashpad)**: DEK·학생 글이 들어갈 수 있어 로컬 덤프를 끈다(`crashReporter` 미사용, 덤프 경로 비움).
- **할당량 넘침**(`QuotaExceededError`): 옮기기는 시작 전에 막는다(§4.1). 평소 쓰기는 '저장 공간이 부족합니다'를 띄우고 그 쓰기를 되돌린다.
- **오프라인**: 동기화는 다음 기회까지 기다리고 상태에 '오프라인'으로 보인다. 앱의 다른 기능은 그대로 쓴다.

## 9. exe 보강(메인)

1. **업데이트 서명·되돌리기**
   - `sig2` = Ed25519(정규 JSON `{version, shell, bundle, sha256, note, date, expires}`). 옛 `sig` 유지. `expires` = 배포 + 120일, 넘으면 경고만.
   - 묶음 안 `manifest.json`(파일별 sha256): 설치 때 전부 확인한다. 켤 때는 `index.html`과 첫 진입 파일만 확인하고, 나머지는 크기·수정 시각이 바뀐 것만 다시 확인한다(비용 줄임).
   - `current.json` = `{version, dir, prev, failedStarts}`. **판정**: React 뿌리가 붙으면 `bundle:alive`(vault·마법사·PIN보다 먼저). 새 판이 **두 번 연속** alive에 못 닿거나 `render-process-gone`·`did-fail-load`가 나면 `prev`로 돌아가고 그 판을 건너뛴다. 사용자가 닫은 것은 실패로 세지 않는다(검토 M9).
   - 1.0 이상을 설치하면 1.0 미만 묶음을 지운다.
2. **Electron fuses**: `afterPack`에서 `@electron/fuses`로 runAsNode·NodeOptions·inspect 인자를 끄고, 쿠키 암호화를 켜고, file 프로토콜 특권을 끈다.
   - `context.electronPlatformName`·`appOutDir`로 Windows 실행 파일을 찾는다. 포터블 포장 전에 돈다. 빌드 뒤 `npx @electron/fuses read`로 확인한다.
   - **asar 무결성은 켜지 않는다**(electron-builder 25는 해시를 넣지 않고, 해시가 없으면 앱이 강제 종료됨, §13). 화면 묶음은 §9.1 manifest가 지킨다.
   - RunAsNode에 기대는 코드는 없다(검토 확인).
3. **권한 처리기**: `clipboard-sanitized-write`(노트·누가기록 복사)만 허용하고, 마이크를 포함한 나머지는 거부한다. 지금 마이크를 쓰는 기능은 없다. 받아쓰기는 녹음 파일을 쓴다(검토 M11).
4. **경로 통로**: 노트 '폴더' 블록은 대화상자로 고른 폴더(메인이 기억) 안만 허용한다. `stt:run`은 대화상자로 고른 파일과 **끌어 놓은 파일**만 받는다(preload가 놓은 파일 경로를 메인에 등록하고, 메인이 그 목록과 맞춤).
5. **외부 프로그램**: `claude`·`agy`는 절대 경로로, 앱 자료 폴더 `ai-work`에서 실행한다. Antigravity에는 표준 입력으로 넘긴다. 안 되는 판이면 권한을 좁힌 임시 파일로 넘기고 곧 지운다.
6. **CSP**: `form-action 'none'`, `frame-src 'none'`, `object-src 'none'`을 더하고 `raw.githubusercontent.com`을 뺀다. 드라이브 주소는 넣지 않는다(메인만 부름).
7. **닫기 전 저장**: 창 `close`를 한 번 막고 `app:before-close`를 보낸다.
   - 화면은 **`await flushAll()`**(모든 미뤄 둔 저장의 Promise를 기다리고 Dexie 묶음 완료까지, 검토 B4) → `app:close-ok`.
   - 그 뒤 남은 시간 안에서 동기화 올리기를 해 본다. 전체 상한은 3초.
   - `query-session-end`(윈도우 로그오프·종료)에서는 막지 않는다(막으면 '종료를 막는 앱' 창이 뜸). 같은 저장을 곧바로 시작만 한다.
   - 이를 위해 `registerFlush` 작업은 Promise를 돌려주게 바꾼다.
8. **자동 실행·바로가기**: 실제 exe 경로는 `PORTABLE_EXECUTABLE_FILE`이다.
   - '컴퓨터를 켜면 Watson 열기'는 `setLoginItemSettings({openAtLogin, path})`. '바탕화면 바로가기'는 `writeShortcutLink`.
   - 켤 때 경로가 바뀌었으면 고친다. 0.13 .cmd 도우미는 지운다.
9. **유지**: 창 격리·샌드박스·IPC 발신자 확인·app 프로토콜 경로 검사·업데이트 Ed25519.

## 10. 1.0.0 exe에 미리 넣는 메인 API(고정 목록)
1.0.x 동기화가 exe를 다시 내지 않도록 1.0.0 exe에 다음을 모두 넣는다. 각각 Node 시험으로 덮는다.
- `vault:status`·`vault:unlock-dpapi`·`vault:store`(dpapi·pass·recovery 쓰기, 원자적)·`vault:read-backup`.
- `device:info`(컴퓨터 이름, exe 경로).
- `google:login(scopes, {incremental})`·`google:status`(계정·받은 권한)·`google:logout`.
- `google:api`: 정규화 허용 목록, 바이너리 본문·응답, 응답 머리글, `google:upload-resumable(meta, bytes)`, `google:download(fileId)`.
- `bundle:alive`·`app:before-close`/`app:close-ok`.
- `paths:pick-folder`·`paths:register-drop`.
- `autostart:get/set`·`shortcut:create`.

## 11. 시험·검증

**자동(Vitest, fake-indexeddb)**
- **미들웨어**
  - 표마다 넣기·바꾸기·지우기·색인 검색·고유 색인·`modify`·`update`·커서·liveQuery·`filter`.
  - 원시 저장값에 표본 이름·글·전화가 없는지.
  - `_enc` 붙은 값의 보통 쓰기 거부, 손상·변조·다른 열쇠 행은 보통 읽기에서 빠지고 덮어쓰지 않음.
  - 도장(시계 앞선 행), 병합 쓰기 예외, 자동 묶음은 병합 불가.
  - 정규 JSON(키 순서 다른 같은 객체 → 같은 해시).
- **옮기기**
  - 평문 → 암호화 후 내용이 같은지.
  - 단계별 중단 뒤 옛 DB가 그대로이고 다음 실행 때 처음부터 하는지.
  - 암호구 틀림·잊음, 할당량 부족, 결정적 id 바꾸기(신고서·연결이 함께 바뀌는지).
- **vault**: DPAPI 실패 → 암호구·복구 코드, 틀린 암호구 5번, vault.json 손상 → .bak, 암호구 바꾸기, 비동기 safeStorage 불가.
- **복원**: 동기화 꺼짐(병합)·켜짐(도장 + 지움 표시, 다른 PC에 퍼짐).
- **동기화**(메모리 가짜 드라이브)
  - 두 기기·세 기기에서 만들기·고치기·지우기.
  - 충돌 사본(두 PC가 같은 충돌 → 사본 하나), 출결 고유 키(지움 표시 포함).
  - **새 기기 두 대 → 동기화**(결석신고서·기본 글 겹침 없음), 지운 기본 글이 되살아나지 않음.
  - 첨부, 열쇠 다른 기기, 암호구 바뀜, 시계 하루 앞섬, 폴더 지워짐, 첫 PC 경쟁, 네트워크 실패 후 다시, 오래된 기기, 묘비 GC.
  - **같은 자료로 세 번 돌려도 아무것도 쓰지 않음**(끝없는 올리기 없음), 판이 다른 기기의 모르는 칸 보존.
- **메인(Node)**: 구글 주소 정규화(우회 목록), `sig2`·manifest·되돌리기 판정(사용자 닫기는 실패 아님, 두 번 연속만), 경로 통로, 닫기 손잡이 시간 초과, 이어 올리기 다시 시도.

**실제 Chromium(Playwright, 웹 빌드에 시험용 열쇠 주입)**: 첨부 50MB 넣기·읽기·백업 시간, 1만 행 화면 시간.

**빌드 확인(여기서)**: fuses 값(`@electron/fuses read`), CSP 머리글, 묶음 manifest.

## 13. 확인한 사실
- **Dexie**: 묶음 안에서 Dexie 밖 비동기 API를 부르면 묶음이 일찍 끝난다(PrematureCommitError). 검토자가 fake-indexeddb로 실측: 단계 10 미들웨어에서 `getMany` 뒤 `mutate`가 bulkPut·modify·update·anyOf·고유 색인 위반·filter·liveQuery 모두에서 동작했고, 비동기 틈을 넣으면 PrematureCommitError가 났다. liveQuery·관찰은 평문 색인 키만 쓴다. Dexie 4.4.7은 디스크 판이 더 높아도 연다.
- **@noble/ciphers 2.4.0 GCM**: 약 43MB/s, 50MB 1.17초, 작은 행 1만 개 0.5초(검토 실측).
- **safeStorage**: Windows에서 DPAPI로 열쇠를 만들거나 보호한다. 다른 사용자에게서는 지키지만 같은 사용자 공간의 다른 앱에서는 지키지 못한다. 동기 API는 46에서 제거 예정이고, 44.10.2에 비동기 API가 있다(타입 정의 확인).
- **ASAR 무결성**: Windows는 Electron 30+. 빌더가 해시를 넣어야 하고, 없거나 틀리면 강제 종료된다. app-builder-lib 25.1.8에는 `electronFuses` 설정이 없다(v27 문서만).
- **`drive.file`**: 앱이 만들거나 사용자가 연 파일만, 비민감 권한이다. '앱'이 클라이언트 단위인지 프로젝트 단위인지는 문서에 없다. PC끼리는 같은 클라이언트라 무관하고, 1.1 전에 시험한다(안 되면 휴대폰에서 파일 선택기로 폴더 한 번 고르기). 이어 올리기는 5MB 넘는 파일에 필요하다.
- **포터블 exe**: `PORTABLE_EXECUTABLE_FILE`. Electron 44에 `query-session-end`·`setLoginItemSettings`·`writeShortcutLink`가 있다.
- **코드**
  - 색인에 이름·글이 없다(단 `hwpx_templates.name`은 파일 이름 → 새 스키마에서 뺌).
  - 하드 삭제는 출결 묘비 재사용·나이스·구글 다시 받기·복원 `clear()`이다.
  - 비-JSON 저장값: hwpx 양식 바이트, 백업 CryptoKey, 웹 폴더 핸들.
  - 파생 행이 무작위 id다: `reconcileStudent`(reconcile.ts:126-133), `applyEstimate`(estimate.ts:74-78), 기본 글 재시드(store.ts:56-59).
  - `flushAll`은 동기이고 Promise를 기다리지 않는다(flush.ts).
  - 마이크를 쓰는 곳이 없고 클립보드 쓰기는 있다.
  - `createDb`는 App 안에서 바로 열린다(App.tsx:49).
  - 단일 실행 잠금이 있다(main.cjs:45).
