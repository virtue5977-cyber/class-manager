## 1. 자료 전체 암호화

**목표**: 노트북을 도난당하거나 디스크를 복사해도 학생 자료(명단·출결·상담·노트·전달사항…)를 읽을 수 없다.

- **자료 열쇠(DEK)**: 무작위 256비트. 처음 1.0을 켤 때 만든다.
- **열쇠 보관 두 가지**
  1. Windows 보호 저장소(safeStorage, DPAPI)로 감싸 메인 프로세스가 파일로 보관한다. 같은 PC·같은 윈도우 계정이면 아무것도 묻지 않고 열린다.
  2. 백업 암호구로 감싼 사본(PBKDF2 600k + AES-GCM). PC나 윈도우 계정이 바뀌면 이 사본과 암호구로 연다. 드라이브 동기화를 켜면 같은 사본을 드라이브에도 둔다.
- **무엇을 암호화하나**: `device_local`(기기 상태)·`neis_cache`(학교 공개 자료)를 뺀 모든 표. 각 행에서 **색인 칸(id·날짜·student_id·class_id 등)과 `updated_at`·`deleted`만 평문**으로 두고, 나머지는 한 덩어리로 AES-256-GCM 암호화(`_enc`)한다. 색인에는 이름·글이 없다(확인됨).
- **방식**: Dexie DBCore 미들웨어. IndexedDB 묶음 저장(트랜잭션) 안에서 쓰도록 **동기식 암호(@noble/ciphers의 AES-GCM)**를 쓴다(WebCrypto는 비동기라 묶음이 끊긴다).
- **옮기기(마이그레이션)**: 1.0 첫 실행 때, 먼저 백업을 하나 만든 뒤(가능하면) 모든 행을 읽어 암호화해 다시 쓴다. 중간에 꺼져도 다음 실행에서 이어서 한다(행마다 `_enc` 유무로 판단, 읽을 때 평문 행도 읽힘).
- **암호구가 아직 없으면**: 암호화는 DPAPI 열쇠만으로 한다. 화면 위에 '백업 암호구를 정해야 PC를 바꿔도 자료를 열 수 있습니다'를 늘 보인다. 암호구를 정하면 바로 사본(2)을 만든다. 암호구를 바꾸면 사본(2)을 새로 감싼다.
- **열쇠를 못 여는 경우**(다른 PC·계정): '자료 열기' 화면에서 암호구를 묻는다. 맞으면 DPAPI로 다시 감싸 저장한다. 틀리면 5번까지 다시, 그 뒤 '백업 파일에서 복원' 안내.
- **웹 개발 화면·시험 환경**(safeStorage 없음): 암호화 없이 그대로(지금과 같음). 미들웨어는 시험용 열쇠로 따로 시험한다.
- **AI 키**: DB 안에 있으므로 함께 암호화된다(보안 점검 M3 해결).
- **백업 파일**: 지금처럼 스냅숏을 암호구 열쇠로 암호화(미들웨어가 읽을 때 풀어 준 내용). 형식 번호는 그대로 2.

## 2. 구글로 시작(계정 연결)

- 설정에 '구글 계정' 탭(캘린더 탭을 합침). 단추 '구글로 시작'.
- 기본 권한: `openid email profile` + `drive.file`. 모두 비민감이라 경고 화면이 없다.
- 캘린더는 같은 탭의 '캘린더도 연결' 단추로 따로(점진 동의, `include_granted_scopes=true`). 지금 캘린더를 쓰는 사람은 그대로 유지(이미 받은 권한).
- 연결된 계정 이메일과 쓰는 기능을 보여 준다. 로그인 만료·실패는 설정과 홈 띠에 보인다.
- 토큰은 메인 프로세스만. safeStorage를 쓸 수 없으면 저장하지 않는다(평문 저장 제거).
- 메인의 구글 API 통로는 **주소를 해석해 정규화한 뒤** 허용 목록(`/calendar/v3/…`, `/drive/v3/…`, `/upload/drive/v3/…`)만 허용한다(`../` 우회 막음). 업로드는 바이너리 본문을 받는다.
- 학교 구글 계정에서 `admin_policy_enforced`·`access_not_configured`가 오면 '개인 Gmail을 쓰거나 학교 관리자에게 앱 등록을 부탁하세요' 안내.

## 3. 드라이브 동기화(PC 여러 대)

**목표**: 학교 PC와 집 PC가 같은 자료를 본다. 드라이브에는 암호화된 파일만 있다. 1.1 휴대폰 앱이 같은 방식을 쓴다.

- **드라이브 'Watson' 폴더**(내 드라이브에 보임)
  - `watson-key.json`: 자료 열쇠를 암호구로 감싼 사본(1의 2번). 새 PC는 암호구로 열쇠를 얻는다.
  - `devices/<기기ID>.wsync`: 그 기기의 전체 스냅숏(첨부 내용 제외)을 자료 열쇠로 암호화.
  - `files/<첨부ID>.wfile`: 첨부 내용(자료 열쇠로 암호화). 한 번만 올린다.
- **켜는 법**: '구글로 시작' → '이 PC 동기화 켜기'. 백업 암호구가 있어야 켤 수 있다. 드라이브에 이미 `watson-key.json`이 있으면(다른 PC에서 켬) 암호구로 열고, 이 PC의 자료와 드라이브 자료를 **합친다**(아래 규칙). 이 PC 자료 열쇠와 다르면 이 PC 자료를 드라이브 열쇠로 다시 암호화한다.
- **언제**: 앱을 켤 때, 바뀐 뒤 1분 조용하면, 10분마다, 창이 다시 보일 때, 창을 닫기 전(가능하면).
- **합치는 규칙**: 다른 기기 파일 중 마지막으로 본 뒤 바뀐 것만 받는다. 표마다 같은 id 행은 `updated_at`이 늦은 쪽이 이긴다(지운 표시도 행이라 지움도 전해짐). 합칠 때는 `updated_at`을 바꾸지 않는다.
  - **노트**: 양쪽 다 마지막 동기화 뒤 고쳤고 내용이 다르면 진 쪽을 '(충돌 사본) 제목' 노트로 남긴다.
  - **같은 학생·같은 날·같은 종류 출결**(유일 색인)이 서로 다른 id로 생기면 늦은 쪽 하나만 남긴다.
- **올리기**: 이 기기에 바뀐 것이 있으면 내 스냅숏 파일을 덮어쓴다. 새 첨부는 `files/`에 올린다.
- **화면**: 설정 '구글 계정'에 마지막 동기화 시각·기기 목록(이름·마지막 시각)·지금 동기화·이 기기 연결 끊기. 실패하면 이유를 보인다(조용히 실패하지 않음).
- **안전**: 합치기 전 로컬 안전 백업(하루 한 번). 다른 기기 파일을 풀 수 없으면(열쇠 다름) 그 기기는 건너뛰고 알린다.

## 4. exe 보강(보안 점검 반영)

1. **업데이트**: `update.json` 전체(버전·셸·묶음·해시·안내·날짜·만료일)에 서명(`sig2`). 옛 exe를 위한 `sig`도 그대로 둔다. 묶음 안 파일 해시 목록을 설치 때 저장하고 켤 때 확인한다. 이전 판을 남겨 두고, 새 판이 첫 화면을 그리지 못하면 다음 실행 때 이전 판으로 돌아간다.
2. **Electron 안전 스위치(fuses)**: RunAsNode·NodeOptions·inspect 끔, asar 무결성·asar에서만 실행 켬.
3. **권한**: 마이크(음성 받아쓰기)만 허용, 나머지 거부.
4. **폴더 통로**: 노트 폴더 블록은 사용자가 고른 폴더(메인이 기억) 안에서만 목록·열기.
5. **외부 프로그램**: `claude`·`agy`는 절대 경로로 찾고, 앱 자료 폴더 안 전용 폴더에서 실행. Antigravity에 글을 명령줄이 아니라 표준 입력으로 넘긴다.
6. **CSP**: `form-action 'none'`, `frame-src 'none'`, `raw.githubusercontent.com` 제거, 드라이브 주소는 메인만 부르므로 CSP에 넣지 않는다.
7. **창 닫기 전 저장**: 메인이 닫기 전에 화면에 '닫는다'를 알리고, 화면이 미뤄 둔 저장과 동기화 올리기를 끝냈다고 답하면(최대 3초) 닫는다.
8. **자동 실행·바로가기 단추**: 설정 '화면'에 '컴퓨터를 켜면 Watson 열기'(로그인 항목)·'바탕화면 바로가기 만들기'. 0.13의 .cmd 도우미는 지운다.

## 시험·검증
- 미들웨어: 표마다 넣기·바꾸기·지우기·색인 검색·묶음 저장이 암호화된 채 그대로 되는지, 디스크(원시 IndexedDB)에 이름·글이 없는지.
- 옮기기: 평문 DB → 암호화, 중간에 끊긴 뒤 이어하기.
- 열쇠: DPAPI 실패 → 암호구로 열기, 틀린 암호구.
- 동기화: 가짜 드라이브(메모리)로 두 기기 시나리오(새로 만들기·고치기·지우기·충돌 노트·출결 중복·첨부·열쇠 다른 기기).
- 메인: 구글 주소 정규화, 업데이트 서명·해시 목록·되돌리기는 Node 시험으로.
- 실제 exe를 빌드해 Windows 없이 확인 가능한 것(asar·fuses 설정)은 빌드 결과로 확인. Windows 실행 확인은 선생님 PC에서.
