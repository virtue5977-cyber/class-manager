# Watson 1.0.2 + 드라이브 동기화 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 1.0.2 작은 고치기 네 가지와 드라이브 동기화(설계서 §7)를 화면 업데이트로 낸다. 새 exe는 내지 않는다.

**Architecture:**
- 동기화 로직은 순수 모듈로 나눈다.
  - `syncCore`: 표 고르기, 해시, 합치기 판정, 겹침 정리
  - `wsync`: 스냅숏·첨부 파일 형식
  - `driveStore`: 구글 드라이브 폴더·파일
- 이 셋을 `syncOnce`가 하나의 병합 묶음으로 엮는다.
- 시험은 메모리 가짜 드라이브와 두 개의 vault DB로 'PC 두 대'를 흉내 낸다.

**Tech Stack:** React 18, TS, Dexie 4.4.7 + vault 미들웨어, @noble/ciphers·@noble/hashes, CompressionStream(gzip), Vitest + fake-indexeddb, Playwright(Chromium).

**Spec:** `docs/superpowers/specs/2026-11-13-watson-1-0.md` §7(동기화), §3(열쇠), §5.5(병합 쓰기). 1.0.0 후속 목록은 `docs/superpowers/plans/2026-11-13-watson-1-0-0-followups.md`에 있다.

## Global Constraints

**exe와 배포**
- exe(`electron/`)를 바꿔도 이번 배포에는 들어가지 않는다. 화면이 쓰는 메인 API는 1.0.1에 이미 있는 것만 쓴다.
  - 구글: `google.{status,login,logout,api,uploadResumable,download}`
  - 열쇠 파일: `vault.{status,store,...}`
  - 그 밖: `file.saveAs`, `bundle.alive`, `app.onBeforeClose`
- 배포는 `MIN_SHELL=7` 렌더러 묶음 1.0.2로 한다.

**자료 보호**
- 학생 자료는 드라이브에 암호문으로만 올린다.
  - `.wsync` aad는 `watson-sync:v1:<deviceId>`, `.wfile` aad는 `watson-file:v1:<blobId>`다.
  - 형식은 `0x01 ‖ iv(12) ‖ AES-256-GCM`이고, DEK는 vault의 DEK를 그대로 쓴다.
- 평문 표(`meta`, `sync_rows`)에는 학생 글이나 그 해시를 두지 않는다.
  - 행 해시는 `HMAC-SHA256(syncKey, 정규 JSON(행))`으로 만든다.
  - `syncKey = HKDF-SHA256(DEK, salt 없음, info 'watson-sync-hash:v1', 32바이트)`이다.
  - 맨 SHA-256은 쓰지 않는다. 짧은 출결 행은 추측으로 되찾을 수 있기 때문이다.

**동기화 규칙**
- 합칠 때 이기는 순서는 **살아 있음 > `updated_at` 늦음 > id 큼**이다.
- 합치기는 `mergeWrite` 묶음 하나 안에서 한다. 쓰는 것은 이긴 값이 로컬과 다른 행뿐이다.
- 시간 기준값
  - 오래된 기기: 90일 동안 올리지 않은 기기
  - 지움 표시 정리: 180일이 지난 것
  - 조용해진 뒤 동기화: 60초
  - 주기 동기화: 10분

**작업 규칙**
- 화면 문구는 한국어로 쓰고, 지울 때는 '지우기'라는 말을 쓴다. 시험·캡처에는 가상 자료만 쓴다.
- 커밋 끝에는 아래 두 줄을 넣는다.
  - `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
  - `Claude-Session: https://claude.ai/code/session_01EwSgn7N6GN1X5AZRMvMiTS`

## Review Focus
1. 두 PC가 같은 학생의 같은 날 출결을 서로 다르게 고친 경우, 동기화한 뒤 두 PC가 같은 값 하나로 맞는다. 고유 색인 오류가 나지 않는다(작업 S5 시험 'same-key attendance').
2. 한 PC에서 지운 노트가 다른 PC의 옛 스냅숏 때문에 되살아나지 않는다. 90일 넘은 기기도 마찬가지다(S5 'tombstone', 'stale device').
3. 동기화 도중 창을 닫거나 인터넷이 끊겨도 로컬 자료가 반쯤 바뀐 채로 남지 않는다. 묶음 하나이기 때문이다. 다음 동기화가 이어서 맞춘다(S5 'abort mid-merge').
4. 두 번째 PC의 열쇠가 다를 때 다시 암호화하는 도중 꺼지면, 옛 vault로 그대로 열린다(S6 'rekey interrupted').
5. 드라이브 업로드가 할당량이나 저장 공간 문제로 실패하면, 로컬 자료는 그대로 두고 상태에 오류와 안내가 보인다(S5 'upload fail').

## 드라이브 동기화

### Task S1: 동기화 표·해시·합치기 판정(순수)

**Files:**
- Create: `src/lib/sync/tables.ts`, `src/lib/sync/hash.ts`, `src/lib/sync/merge.ts`, tests

**Interfaces — 표와 해시**
- `SYNC_TABLES`
  - `SYNCED_TABLES`에서 `neis_cache`, `school_calendar`를 뺀 것이다.
  - `google_events`, `device_local`, `meta`, `sync_rows`, `note_blobs`는 원래 SYNCED에 없다.
  - `note_files`는 메타 행만 동기화한다. 내용은 `.wfile`로 간다.
- `syncableRow(table, row): boolean` → `teacher_timetable`에서 `source==='estimated'`면 거짓이다.
- `syncKeyFrom(dek): Uint8Array` → HKDF로 만든다(Global Constraints).
- `rowHash(key, row): string` → HMAC-SHA256(정규 JSON) hex. 정규 JSON은 `canon.ts`를 쓴다.

**Interfaces — 합치기 판정**
- `winner(a, b)`: 이기는 순서는 살아 있음 > `updated_at` > id 문자열 비교. 같으면 a.
- `decide({ local, remote, base, key, table })` → `{ action: 'keep' | 'take' | 'conflict', value, conflictCopy? }`
  - 판정 규칙
    - 로컬 해시 == base이고 원격 해시 ≠ base → take
    - 원격 == base → keep
    - 둘 다 base와 다르고 서로도 다름 → conflict
  - conflict일 때
    - `notes`, `counseling_logs`이면 진 쪽 사본 `{ ...진쪽, id: 'conflict:'+id+':'+hash12, conflict_of: id }`를 함께 낸다.
    - 나머지 표는 `winner`로 정한다.
  - local만 있으면 keep, remote만 있으면 take다.
- `dedupe(table, rows)` → `{ keep: Row[], hardDelete: id[] }`
  - `attendance`: `student_id + date + kind`가 같으면 winner 하나만 남긴다(지움 표시 행도 포함).
  - `ai_prompts`: kind별로 active인 것 가운데 가장 늦은 것만 active로 두고, 나머지는 `active:false`로 바꾼다(이때 updated_at을 찍는다).
  - `notes` 전달사항 짝: `notice_date`가 같은 짝 노트가 여럿이면 가장 늦게 고친 것만 짝으로 두고, 나머지는 짝 필드만 비운다. 실제 칸 이름은 `src/lib/notices/noteSync.ts`를 grep해서 확인한다.
  - `classes`는 합치지 않는다.

**Steps**
- [ ] **Step 1:** 실패하는 시험을 쓴다.
  - 이기는 순서의 세 가지 경우
  - `decide`의 다섯 가지 경우
  - 노트 충돌 사본 id가 결정적이다(같은 입력이면 같은 id)
  - 출결 같은 키 세 개(그중 하나는 지움 표시) → 하나만 남고 둘은 hardDelete
  - 지시문 active 정리
  - `rowHash`가 키마다 다르고, 같은 행·같은 키면 같다
  - 추정 시간표는 거른다
- [ ] **Step 2–4:** FAIL → 구현 → PASS
- [ ] **Step 5:** 커밋한다.
