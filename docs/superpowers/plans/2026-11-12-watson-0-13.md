# Watson 0.13 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 설계서 11을 반영한다(채팅 대기 표시, 노트 서식·단축키·한글 복사, 노트↔전달사항 연동과 @노트, 누가기록, 바로가기 도우미).

**Architecture:**
- React 화면과 lib만 바꾼다.
- 저장 형식은 선택 필드만 더한다: NoteBlock.marks/links, NoteRec.notice_date, NoticeItemRec.block_id/parts, CounselingLogRec.kind.
- exe는 바꾸지 않는다.

**Tech Stack:** React 18, TS, Vite, Dexie, Vitest(jsdom), Playwright.

**Spec:** docs/superpowers/specs/2026-11-12-watson-0-13.md

## Global Constraints
- exe 무변경. 업데이트 shell 1. 판 0.13.0.
- 가상 학생만 캡처한다. AI로 보내기 전에 학생 이름을 가린다.
- 쉬운 우리말로 쓴다.
- 한글 입력 중(isComposing)에는 단축키·Enter 처리를 하지 않는다.

## Review Focus
- 한글 조합 중 contentEditable 입력: 조합이 깨지거나 글자가 두 번 들어가면 안 된다.
- marks 위치 옮기기: 앞에 넣기, 지우기, 줄 나누기·합치기, 붙여넣기 뒤에도 서식이 그 글자에 남아야 한다.
- 짝 노트 ↔ 전달사항 맞추기: 무한 반복이 없어야 한다. 여러 날 전달사항은 건드리지 않는다. 노트를 지우면 전달사항은 남는다.
- 예전 기록(kind 없음, marks 없음, notice_date 없음)이 그대로 열려야 한다.
- 대기 중에 연달아 보낸 말은 순서대로 처리하고, 실패해도 다음 말은 계속 처리한다.

### Task 1: 채팅 대기
- `src/lib/command/pending.ts`:
  - 모듈 저장소 `addPending({input, thread}) → id`, `removePending(id)`, `usePending()`(useSyncExternalStore).
  - `enqueue(fn)`: 줄 세워 차례로 실행한다.
- `CommandBar.run`:
  - 입력칸을 바로 비운다.
  - pending에 넣고, enqueue 안에서 executeInput을 부른 뒤 pending에서 뺀다.
  - '실행' 단추는 busy 때도 쓸 수 있다.
- `ChatLog`:
  - 기록 뒤에 그 thread의 pending을 그린다: 내 말풍선, 그리고 300ms 뒤 `.typing` 말풍선(● ● ●, aria-label '대답을 만드는 중').
  - 끝까지 스크롤한다.
- `ResultCard`: status '실패'이면 '다시 보내기' 단추를 단다.
- 테스트:
  - pending.test: 차례 실행, 실패해도 다음으로 넘어간다.
  - ChatLog.test: pending 말풍선과 점 표시.
  - CommandBar.test: 보내면 입력칸이 비고, 실행이 끝나면 pending이 사라진다.

### Task 2: 노트 단축키
- `blocks.ts`:
  - `noteShortcut`: Ctrl+1..6을 p, h1, h2, bullet, number, check로 읽는다.
  - 예전 Ctrl+Shift·Ctrl+Alt 조합(0,1,2,7,8,9,T)도 그대로 받는다.
- `NoteEditor`:
  - 글 칸에서 Ctrl+숫자를 받으면 preventDefault와 stopPropagation을 한다. 앱의 메뉴 이동은 document 단계에서 듣기 때문이다. Shortcuts에서 `.nb-text` 안이면 Ctrl+숫자를 건너뛰게 한다.
  - Ctrl+Enter로 체크를 켜고 끈다.
- 단축키 표와 슬래시 힌트를 고친다.
- 테스트: blocks.test, shortcuts.test(노트 안이면 null).

### Task 3: 서식 모델(lib)
- `src/lib/notes/marks.ts`:
  - `type Mark = {from,to,b?,u?,i?,s?,color?,bg?,font?,size?}`
  - `applyMark(marks, from, to, patch)`: 켜기/끄기를 토글한다. 같은 값이면 끈다.
  - `shiftMarks(marks, oldText, newText)`: 앞뒤 같은 부분으로 고친 구간을 찾아 위치를 옮긴다.
  - `splitMarks(marks, at)`, `joinMarks(a, aLen, b)`
  - `segments(text, marks)`: 겹치지 않는 조각과 각 조각의 스타일
  - `marksAt(marks, at)`
- `NoteBlock.marks?`, `NoteBlock.links?: {from,to,note}[]`를 더한다. links도 같은 shift/split/join을 쓴다(`Range` 공용).
- `blocks.ts`의 splitBlock과 merge(Backspace)가 marks와 links를 나누고 합치게 한다.
- 테스트: marks.test에 위 함수마다 2~3개.

### Task 4: 서식 편집기
- `src/pages/notes/RichLine.tsx`:
  - contentEditable 한 줄. props `{text, marks, links, onChange(text, marks, links), onKeyDown, ...}`.
  - 그리기: segments를 span으로 만든다.
  - 입력: `input` 이벤트에서 textContent를 읽어 shiftMarks한다.
  - 조합 중(compositionstart~end)에는 다시 그리지 않는다.
  - 커서: 다시 그린 뒤 글자 위치로 되돌린다(`getCaret(el)`, `setCaret(el, n)`).
  - 붙여넣기는 text/plain만 받는다. 줄바꿈이 있으면 여러 블록으로 나눈다(기존 동작).
  - 같은 위치를 쓰도록 selectionStart·selectionEnd 대신 `getSel(el) → {start,end}`를 둔다. caretNav와 slash 처리도 이것을 쓴다.
- `FormatBar.tsx`: 고른 범위가 있으면 위에 뜬다. B U I S, 글자색 8, 형광펜 5, 글꼴 9, 크기 3. Ctrl+B/U/I.
- `NoteEditor`의 textarea를 RichLine으로 바꾼다. 줄바꿈 CSS(white-space: pre-wrap; overflow-wrap:anywhere)를 넣어 버그를 고친다.
- 테스트: NotesPage.test는 기존 테스트가 통과하도록 고친다. 추가: 서식 주기와 저장, Ctrl+B, 긴 줄 줄바꿈(스타일 검사).

### Task 5: 한글로 복사
- `src/lib/notes/toHtml.ts`:
  - `noteToHtml(note, sel?)`: 한글이 읽는 inline style만 쓴다. 쓰는 것: font-family, font-size(pt), font-weight, text-decoration, color, background-color, margin-left, table border.
  - `noteToPlain(note)`
- 머리의 '한글로 복사' 단추: ClipboardItem(text/html, text/plain). 안 되면 execCommand('copy')와 숨긴 div로 한다.
- 고른 상태에서 Ctrl+C: copy 이벤트에서 setData로 html을 넣는다.
- 확인 스크립트: 가상 노트 5종을 html로 만들고 → hwpx 스킬로 hwpx를 만들고 → 렌더해서 캡처한다.
- 테스트: toHtml.test.

### Task 6: 노트↔전달사항
- `src/lib/notices/noteSync.ts`:
  - `noticeNoteOf(db, date)`
  - `openNoticeNote(db, date) → NoteRec`: 없으면 만든다. 제목 `[전달사항] M/D(요)`. 그날 하루짜리 항목을 블록으로 넣고 block_id를 단다.
  - `syncNoteToNotices(db, note)`: 짝 노트를 저장하면 글 블록과 그날 하루짜리 항목을 맞춘다.
    - block_id로 짝을 찾는다.
    - 새 블록은 항목으로 더한다.
    - 없어진 블록의 항목은 지운다.
    - 글, 체크, 순서, parts를 맞춘다.
  - `syncNoticesToNote(db, date)`: 전달사항을 고치는 lib 함수(add/update/delete/move/clear)가 끝나면 부른다.
  - 노트에서 온 저장 안에서 다시 노트를 쓰지 않도록 `origin` 표시로 반복을 막는다.
  - `linkNoteToDate(db, noteId, date, mode: 'merge'|'replace')`
  - `unlinkNoticeNote(db, noteId)`
- `notes.ts`:
  - saveNoteContent와 체크 변경 뒤에 짝이면 sync한다.
  - deleteNote는 연결만 끊는다(항목 block_id를 지운다).
  - `listNotes` 정렬: 오늘과 앞날짜의 notice_date 노트가 먼저, 그다음 고정, order, 최근 순.
- 화면:
  - NoticeTab 머리에 '노트로 열기' 아이콘을 둔다. 지금의 '노트로 보내기'를 이것으로 바꾼다.
  - NoteEditor:
    - '노트 전체를 전달사항으로'를 제목 줄로 옮긴다. 날짜 하나를 고른다. 짝이 있으면 합치기/바꾸기를 묻는다.
    - 짝 노트에는 [전달사항] 표와 '연결 끊기'.
  - NotesPage 목록과 NoteBox에 [전달사항] 표.
- 테스트: noteSync.test(만들기, 양쪽 맞추기, 여러 날 제외, 지우기 뒤 남음, 반복 없음), NotesPage/NoticeTab 각 1.
